@@ brief
- Tout le module tient dans un projet Python avec Jupyter. **uv** gère le projet : `uv init` le crée, `uv add` installe une bibliothèque, `uv run` lance une commande dans son environnement.
- Les bibliothèques du module : `requests` (télécharger la FAQ), `minsearch` (un petit moteur de recherche en mémoire), `openai` (le client du LLM), `jupyter` et `python-dotenv` (lire un fichier `.env`).
- 🔑 La **clé d'API** est un mot de passe qui donne accès à ta carte bancaire. Elle ne doit **jamais** être commitée. Le cours la range dans un fichier `.env` ignoré par Git. Dans ton Codespace, on fait plus sûr : un **secret Codespaces**.
- OpenAI demande un dépôt minimum de 5 $. Une requête de ce module coûte une fraction de centime avec `gpt-5.4-mini`. Le cours conseille un **projet OpenAI dédié**, pour voir exactement ce que le cours te coûte.
- Les fournisseurs « compatibles OpenAI » (Groq, Gemini, Ollama) s'utilisent avec le même client : on change `api_key` et `base_url`.

@@ codespaces

- Ta clé va dans un **secret Codespaces** nommé `OPENAI_API_KEY`. Le client `OpenAI()` lit cette variable tout seul : tu n'as pas besoin de `.env`.

@@ guide
### 1. Le secret Codespaces

Sur github.com : ta photo en haut à droite → **Settings** → **Codespaces** (dans le menu de gauche) → **New secret**.

- Name : `OPENAI_API_KEY`
- Value : ta clé, qui commence par `sk-`
- Repository access : choisis `gitabdelhub/llm-zoomcamp`

Si ton Codespace était déjà ouvert, il ne voit pas encore le secret : GitHub propose de le recharger. Sinon, arrête-le et relance-le.

Vérifie dans le terminal **sans afficher la clé** :

~~~bash
echo ${OPENAI_API_KEY:0:3}
~~~

`${VARIABLE:0:3}` n'affiche que les 3 premiers caractères. Tu dois voir `sk-`. Ne fais jamais `echo $OPENAI_API_KEY` en entier : le terminal garde un historique, et une capture d'écran part vite.

### 2. Le projet

~~~bash
mkdir -p /workspaces/llm-zoomcamp/mon-travail/module-01
cd /workspaces/llm-zoomcamp/mon-travail/module-01
uv init
uv add requests minsearch openai jupyter python-dotenv
~~~

Le cours demande Python 3.14 ou plus. Si `uv init` a pris une version plus ancienne, `uv python pin 3.14` puis `uv sync` la télécharge et l'utilise.

### 3. Le .gitignore

Crée `mon-travail/module-01/.gitignore` avec ces lignes :

~~~text
.env
.venv/
*.db
.ipynb_checkpoints/
~~~

Puis `git status` : tu dois voir `pyproject.toml`, `uv.lock`, `.gitignore`, mais pas `.venv`. Vérifie une règle avec `git check-ignore -v .env` : Git te dit quelle ligne de quel fichier l'ignore.

### 4. Le notebook

Deux façons de faire, choisis-en une :

- dans VS Code, crée `notebook.ipynb`, puis **Select Kernel** → **Python Environments** → le `.venv` de `mon-travail/module-01` ;
- ou lance `uv run jupyter notebook` et ouvre le lien du port 8888 dans l'onglet Ports.

### 5. La cellule de vérification

~~~python
import os
from openai import OpenAI

cle = os.environ.get("OPENAI_API_KEY")
print("Clé trouvée" if cle else "Pas de clé", "| longueur :", len(cle or ""))

openai_client = OpenAI()
~~~

On affiche la longueur, jamais la clé. Une cellule de notebook s'enregistre **avec sa sortie** : si elle affichait la clé, tu la commiterais avec le notebook.

@@ hints
- `echo ${OPENAI_API_KEY:0:3}` n'affiche rien : ton Codespace a démarré avant le secret, ou le secret n'a pas accès à ce dépôt. Vérifie « Repository access », puis arrête et relance le Codespace.
- `uv: command not found` : `pip install uv`, puis recommence.
- VS Code ne propose pas le `.venv` comme kernel : lance d'abord `uv sync` dans le dossier, puis **Select Kernel** → **Select Another Kernel** → **Python Environments**.

@@ solution
Les commandes, dans l'ordre, depuis le terminal du Codespace :

~~~bash
# Le dossier du module, dans ton fork
mkdir -p /workspaces/llm-zoomcamp/mon-travail/module-01
cd /workspaces/llm-zoomcamp/mon-travail/module-01

# Le projet et ses bibliothèques
uv init
uv add requests minsearch openai jupyter python-dotenv

# Ce qui ne doit jamais partir sur GitHub
printf '.env\n.venv/\n*.db\n.ipynb_checkpoints/\n' > .gitignore

# On vérifie : pyproject.toml, uv.lock et .gitignore apparaissent, .venv non
git status --short .
git check-ignore -v .env
~~~

Et la première cellule du notebook :

~~~python
import os
from openai import OpenAI

# On vérifie la présence de la clé sans jamais l'afficher
cle = os.environ.get("OPENAI_API_KEY")
print("Clé trouvée" if cle else "Pas de clé", "| longueur :", len(cle or ""))

# OpenAI() lit OPENAI_API_KEY dans l'environnement : le secret Codespaces suffit
openai_client = OpenAI()
~~~

Sortie attendue : `Clé trouvée | longueur : ` suivi d'un nombre (souvent plus de 100 caractères pour une clé de projet).

@@ explain
Pourquoi un secret Codespaces est-il plus sûr qu'un fichier `.env` ? Et que fais-tu tout de suite si ta clé fuit sur GitHub ?

@@ cles
- Les secrets Codespaces | github codespaces secrets environment variables | La clé ne touche jamais les fichiers du dépôt : impossible de la commiter par erreur.
- La rotation d'une clé qui a fuité | revoke rotate leaked api key | Une clé publiée est utilisée par des robots en quelques minutes : on la révoque d'abord, on enquête ensuite.
- Les fournisseurs compatibles OpenAI | openai compatible api base_url groq gemini ollama | Le même code marche avec un autre fournisseur, souvent moins cher ou gratuit.
