@@ brief
- `llm(prompt)` envoie un texte au modèle avec `openai_client.responses.create(model="gpt-5.4-mini", input=prompt)` et renvoie `response.output_text`. C'est la **boîte noire** du module : du texte entre, du texte sort.
- Posée telle quelle, la question « I just discovered the course. Can I join now? » reçoit une réponse **générique** : le modèle ne connaît pas nos cours.
- On colle quelques entrées de la FAQ dans un **contexte**, puis on écrit un prompt : une consigne, la question, le contexte. La réponse devient juste.
- 🔑 La consigne « If the answer is not found in the context, respond with "I don't know." » est le **garde-fou** : elle autorise le modèle à ne pas savoir au lieu d'inventer.
- 🔑 Le RAG tient en trois pièces : **chercher** (search), **construire le prompt** (build_prompt), **générer** (llm). Le modèle ne voit que les documents qu'on lui donne : si la recherche rate, la réponse rate aussi.

@@ predict
Ton prompt contient le contexte de la leçon (4 entrées de la FAQ) et la consigne « I don't know ». Tu poses une question dont la réponse **n'est pas** dans ce contexte : « Is this course free? ». Que répond le modèle, et pourquoi ?

@@ predict-answer
En général, il répond **« I don't know. »**. La consigne lui dit de s'appuyer sur le contexte et lui donne une sortie quand la réponse n'y est pas. Sans cette phrase, il répondrait avec ce qu'il croit savoir des cours en ligne, sur le même ton assuré qu'une vraie réponse.

Ce garde-fou **réduit** les hallucinations, mais ne les supprime pas : un modèle peut encore compléter avec ses propres connaissances. Lance la cellule deux ou trois fois et regarde si la réponse change. Au module 4, tu apprendras à **mesurer** ce comportement au lieu de le deviner.

{context}

@@ solution
~~~python
def llm(prompt):
    response = openai_client.responses.create(
        model="gpt-5.4-mini",
        input=prompt
    )
    return response.output_text


context = """
Mon LLM Zoomcamp is a personal course site built on top of the official LLM Zoomcamp repository.
All lessons are open: nothing is locked, and there are no dates or deadlines.
Progress is saved in the browser (localStorage), not on a server.
Each finished lesson gives XP: 20 for a full lesson, 10 for a short one.
Homework is delivered in the mon-travail folder of the fork.
"""


def rag_manuel(question, context):
    prompt = f"""
Your task is to answer questions from the course participants
based on the provided context.

Use the context to find relevant information and provide accurate
answers. If the answer is not found in the context,
respond with "I don't know."

Question:
{question}

Context:
{context}
"""
    return llm(prompt)


questions = [
    "Is there a deadline for the lessons?",      # dans le contexte
    "Can I get a certificate from this site?",   # hors du contexte
    "Où est enregistrée ma progression ?",       # en français
]

for q in questions:
    print(q)
    print("→", rag_manuel(q, context))
    print()
~~~

Ce que tu devrais observer, sans garantie car le modèle n'est pas déterministe :

- question 1 : « No, there are no dates or deadlines », **fondée** sur le contexte ;
- question 2 : « I don't know » : le contexte ne parle pas de certificat ;
- question 3 : la bonne réponse (le navigateur, localStorage), parfois en anglais, parfois en français.

@@ selfcheck
- `llm("Hey, what's up?")` répond : la clé et le client marchent
- La question 1 reçoit une réponse qui reprend un fait de ton contexte
- La question 2 reçoit « I don't know » (ou une réponse qui dit que l'information manque)
- Tu as noté la langue de la réponse à la question 3
- Tu sais montrer, dans ton code, où sont les trois pièces du RAG : le contexte (la future recherche), le prompt, l'appel au modèle

@@ breakfix
Provoque l'erreur que tout le monde rencontre au début : lance le client **sans clé**. Dans le terminal du Codespace :

~~~bash
env -u OPENAI_API_KEY uv run python -c "from openai import OpenAI; OpenAI()"
~~~

`env -u` lance la commande avec la variable retirée, sans toucher à ton secret. Lis l'erreur : quelle classe d'erreur, à quelle ligne de ton code, et que te demande-t-elle ?

@@ breakfix-hints
- Une trace Python se lit de **bas en haut** : la dernière ligne donne la cause.
- Regarde **quand** l'erreur arrive : à l'appel au modèle, ou avant ?
- Le message cite le nom exact de la variable d'environnement attendue.

@@ breakfix-answer
Tu obtiens une `openai.OpenAIError` dès `OpenAI()`, **avant** tout appel réseau. Avec `openai` 3.51 le texte est : `Missing credentials. Please pass an api_key ... or set the OPENAI_API_KEY ... environment variable.` Les versions plus anciennes disaient `The api_key client option must be set...`. Le sens est le même : le client cherche `OPENAI_API_KEY` et ne la trouve pas.

La réparation : le secret Codespaces de la leçon 2, puis un redémarrage du Codespace.

Les trois autres erreurs à reconnaître, une fois la clé présente :

- **401** `AuthenticationError` : la clé est fausse ou révoquée ;
- **429** `RateLimitError` : trop de requêtes, ou `insufficient_quota` quand ton compte n'a plus de crédit ;
- **404** `NotFoundError` : le nom du modèle est mal écrit, ou ton projet n'y a pas accès.

@@ explain
Pourquoi le même modèle répond-il mal sans contexte et bien avec ? Et que se passe-t-il si le bon document n'est pas dans le contexte ?

@@ cles
- Le grounding (ancrer la réponse dans des sources) | LLM grounding context RAG | C'est la promesse du RAG : le modèle répond à partir de tes documents, pas de sa mémoire.
- La fenêtre de contexte | LLM context window tokens | Tout ce que le modèle lit tient dans une limite de tokens : c'est pour ça qu'on choisit 5 documents au lieu de toute la FAQ.
- Le non-déterminisme des LLM | LLM non deterministic output temperature | La même question peut donner deux réponses différentes : on teste plusieurs fois et, plus tard, on mesure.
