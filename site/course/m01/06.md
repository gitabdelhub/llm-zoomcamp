@@ brief
- Le modèle ne voit nos documents que si on les met dans le prompt. On le coupe en deux parties.
- 🔑 Les **instructions** (ou *system prompt*) disent au modèle son rôle et comment répondre. Elles ne changent jamais. Le **prompt utilisateur** change à chaque question : il porte la question et le contexte trouvé.
- `build_context(search_results)` transforme la liste de dictionnaires en **un seul texte** : pour chaque document, la section, `Q: ...` et `A: ...`.
- `build_prompt(question, search_results)` remplit le modèle `USER_PROMPT_TEMPLATE` avec `.format(question=..., context=...)`.
- Le prompt est le **pont** entre la recherche et le modèle. Un mauvais prompt laisse le modèle ignorer le contexte. Au module 4, tu mesureras la qualité d'un prompt au lieu de la deviner.

@@ predict
La recherche ne trouve rien : `search_results = []`. Tu construis quand même le prompt avec `build_prompt(question, [])` et tu l'envoies au modèle avec les instructions de la leçon. Que contient le prompt, et que répond le modèle ?

@@ predict-answer
`build_context([])` renvoie une **chaîne vide**. Le prompt contient la question, puis `Context:` suivi de rien. Aucune erreur Python : tout « marche ».

Avec la consigne « I don't know », le modèle répond en général **« I don't know. »**. C'est le bon comportement pour le modèle, mais pas pour l'étudiant : souvent, la réponse existe dans la FAQ et c'est la recherche qui a raté (un filtre mal écrit, comme à la leçon 5). Le prompt ne peut pas réparer une recherche vide ; il peut seulement le dire clairement.

@@ practice
Améliore le prompt de la leçon pour qu'un étudiant puisse **vérifier** chaque réponse : des sources numérotées, citées par le modèle, et une réponse dans la langue de la question.

@@ constraints
- `build_context` numérote chaque document `[1]`, `[2]`… et garde son `id`
- Si `search_results` est vide, le contexte vaut exactement `No documents found.`
- Les nouvelles `INSTRUCTIONS` demandent de citer les numéros des sources utilisées, comme `[1]`, et de répondre dans la langue de la question
- La consigne « I don't know » est gardée
- Tu testes avec la question en anglais de la leçon, la même en français, et une recherche vide

@@ guide
### 1. Numéroter

`enumerate(search_results, start=1)` te donne le numéro et le document à chaque tour. Une ligne comme `[1] (id: 0e38656cfb) General Course-Related Questions` suffit comme en-tête de bloc.

### 2. Le cas vide

Teste la liste **avant** la boucle. Un message explicite vaut mieux qu'un contexte vide : il dit au modèle, et à toi quand tu relis le prompt, que la recherche n'a rien trouvé.

### 3. Les instructions

Garde celles de la leçon et ajoute deux phrases : une pour citer les sources entre crochets, une pour la langue. Écris-les en anglais, comme le reste du prompt.

### 4. Regarder avant d'envoyer

`print(build_prompt(question, search_results))` pour chaque test. Le prompt est ce que tu débogues le plus souvent dans un RAG.

### 5. Envoyer

Pour séparer instructions et prompt utilisateur, l'API Responses prend une liste de messages : `input=[{"role": "developer", "content": INSTRUCTIONS}, {"role": "user", "content": prompt}]`. Tu peux aussi les coller l'une après l'autre dans un seul texte, comme à la leçon 3.

@@ hints
- `"\n".join(lines).strip()` : le `strip()` enlève la dernière ligne vide.
- Le numéro sert aux humains, l'`id` sert aux programmes : à la leçon 8, ta fonction renverra les `id` des sources avec la réponse.
- Pour la langue, une consigne simple marche bien : « Answer in the same language as the question. »

@@ solution
~~~python
INSTRUCTIONS = """
Your task is to answer questions from the course participants
based on the provided context.

Use the context to find relevant information and provide accurate
answers. If the answer is not found in the context,
respond with "I don't know."

Cite the sources you used with their number in square brackets, like [1].
Answer in the same language as the question.
"""

USER_PROMPT_TEMPLATE = """
Question:
{question}

Context:
{context}
"""


def build_context(search_results):
    if not search_results:
        return "No documents found."
    lines = []
    for i, doc in enumerate(search_results, start=1):
        lines.append(f"[{i}] (id: {doc['id']}) {doc['section']}")
        lines.append("Q: " + doc["question"])
        lines.append("A: " + doc["answer"])
        lines.append("")
    return "\n".join(lines).strip()


def build_prompt(question, search_results):
    context = build_context(search_results)
    return USER_PROMPT_TEMPLATE.format(question=question, context=context).strip()


def ask(question, search_results):
    prompt = build_prompt(question, search_results)
    response = openai_client.responses.create(
        model="gpt-5.4-mini",
        input=[
            {"role": "developer", "content": INSTRUCTIONS},
            {"role": "user", "content": prompt},
        ],
    )
    return response.output_text


q_en = "I just discovered the course. Can I join now?"
q_fr = "Je viens de découvrir le cours. Est-ce que je peux encore m'inscrire ?"

print(build_prompt(q_en, search(q_en))[:400])
print(ask(q_en, search(q_en)))
print(ask(q_fr, search(q_fr)))
print(ask(q_en, []))
~~~

Ce qu'il faut regarder :

- la réponse anglaise cite `[1]`, l'entrée « Can I still join? » ;
- la question française est **cherchée en français** dans une FAQ en anglais. Sur ma copie de la FAQ, minsearch ne trouve **aucun** document : pas un seul mot en commun. Le contexte vaut `No documents found.` et le modèle répond, en français, qu'il ne sait pas. La réponse existe pourtant. C'est un vrai défaut de ton assistant : la leçon 13 te montrera comment le corriger, en laissant le modèle reformuler la question en anglais. Le module 2 te montrera pourquoi la recherche vectorielle ne suffit pas, à elle seule : il lui faut un modèle d'embeddings **multilingue** ;
- la recherche vide donne « I don't know » : le contexte dit `No documents found.`.

@@ breakfix
Tu veux que le modèle réponde en JSON. Tu ajoutes un exemple à la fin du modèle de prompt :

~~~python
USER_PROMPT_TEMPLATE = """
Question:
{question}

Context:
{context}

Answer as JSON: {"answer": "...", "sources": [1, 2]}
"""
~~~

Lance `build_prompt(q_en, search(q_en))`. Que se passe-t-il, et pourquoi ? Comment garder l'exemple JSON ?

@@ breakfix-hints
- Pour `.format()`, que veulent dire les accolades `{` et `}` ?
- Lis le nom de l'erreur et la clé qu'elle cite : d'où vient ce texte ?
- Le contexte contient parfois des accolades (du code dans les réponses de la FAQ). Est-ce que ça pose aussi problème ?

@@ breakfix-answer
Tu obtiens `KeyError: '"answer"'`. Pour `.format()`, chaque paire `{...}` est un **emplacement à remplir**. Il voit `{"answer": ...}`, cherche un paramètre nommé `"answer"` (guillemets compris) et ne le trouve pas.

La réparation : **doubler** les accolades qui doivent rester telles quelles. `{{` devient `{` et `}}` devient `}` dans le résultat :

~~~python
Answer as JSON: {{"answer": "...", "sources": [1, 2]}}
~~~

Les accolades **à l'intérieur des valeurs** ne posent pas de problème : `.format()` lit seulement le modèle, pas ce qu'il y insère. Une réponse de la FAQ qui contient du code avec `{}` passe sans souci.

Pour du vrai JSON fiable, on ne compte pas sur le prompt : les API proposent des **sorties structurées** (structured outputs), qui imposent un schéma au modèle.

@@ explain
Pourquoi sépare-t-on les instructions et le prompt utilisateur ? Et pourquoi des sources numérotées rendent-elles un assistant plus digne de confiance ?

@@ cles
- Le system prompt (instructions) | system prompt vs user prompt LLM | Les règles fixes d'un assistant vivent à part de ce qui change à chaque question.
- L'injection de prompt | prompt injection attack RAG | Un document de ta base peut contenir « ignore les instructions précédentes » : le modèle lit tout le contexte comme du texte, y compris les pièges.
- Les citations dans un RAG | RAG citations source attribution | Une réponse vérifiable vaut plus qu'une réponse assurée.
- Les sorties structurées | openai structured outputs json schema | Quand un programme doit lire la réponse, on impose un format au lieu de le demander poliment.
