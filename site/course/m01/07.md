@@ brief
- On appelle le modèle avec l'**API Responses** : `openai_client.responses.create(model=..., input=...)`. L'ancienne API, *chat completions*, est dite « legacy ». Attention : Groq ou Gemini proposent un client compatible OpenAI, mais en *chat completions*. Si tu changes de fournisseur, tu appelles `chat.completions` au lieu de `responses`.
- La réponse est un objet : `response.output[0].content[0].text`, ou le raccourci `response.output_text`.
- 🔑 `response.usage` compte les **tokens** : `input_tokens` (ce qu'on envoie), `output_tokens` (ce que le modèle écrit). Un token, c'est environ 3 à 4 caractères en anglais. C'est l'unité de **facturation**.
- 🔑 L'**historique de messages** : une liste de messages avec un rôle. `developer` porte les instructions fixes, `user` porte la question et le contexte. Le modèle n'a pas de mémoire : pour une conversation, on lui renvoie tout l'historique à chaque fois.
- Le RAG complet tient en 3 lignes : `search`, `build_prompt`, `llm`. Chaque pièce se remplace sans toucher aux autres.

@@ practice
Fais de ton RAG un assistant qui connaît son prix : chaque réponse revient avec ce qu'elle a coûté.

@@ constraints
- `INPUT_PRICE` et `OUTPUT_PRICE` en dollars par million de tokens, en haut du notebook
- `llm(instructions, user_prompt)` renvoie le texte **et** l'objet `usage`
- `cost(usage)` renvoie le prix d'un appel en dollars
- `rag(query)` renvoie la réponse et son coût
- 5 questions de ton choix, puis un tableau : tokens d'entrée, tokens de sortie, coût
- Une estimation du coût pour 1000 questions

@@ guide
### 1. Rendre deux valeurs

Une fonction Python peut renvoyer un tuple : `return response.output_text, response.usage`. À l'appel : `answer, usage = llm(...)`.

### 2. Le prix d'un appel

Les prix sont donnés **par million** de tokens. Divise par `1_000_000` (les `_` rendent le nombre lisible, Python les ignore).

### 3. Le tableau

Garde une liste de dictionnaires, un par question, puis `pd.DataFrame(lignes)`. La moyenne de la colonne `cost` multipliée par 1000 donne ton estimation.

### 4. Lire le résultat

Regarde **d'où** vient le coût : les tokens d'entrée (le contexte de 5 documents) ou ceux de sortie (la réponse) ? C'est ce qui te dira quoi optimiser.

@@ hints
- Si `usage` affiche `input_tokens_details=InputTokensDetails(cached_tokens=...)`, ce sont des tokens déjà vus dans une requête récente avec le même début de prompt : ils sont facturés moins cher. Tes instructions fixes en **début** de prompt en profitent.
- `f"{cost:.6f}"` affiche un petit nombre avec 6 décimales.
- Les tokens d'entrée sont presque toujours plus nombreux : 5 réponses de la FAQ pèsent plus lourd que la question et la réponse réunies.

@@ solution
~~~python
import pandas as pd

# Les prix de gpt-5.4-mini, en dollars par million de tokens.
# Vérifie-les sur la page des prix d'OpenAI : ils changent.
INPUT_PRICE = 0.75
OUTPUT_PRICE = 4.50


def llm(instructions, user_prompt, model="gpt-5.4-mini"):
    response = openai_client.responses.create(
        model=model,
        input=[
            {"role": "developer", "content": instructions},
            {"role": "user", "content": user_prompt},
        ],
    )
    return response.output_text, response.usage


def cost(usage):
    return (usage.input_tokens * INPUT_PRICE + usage.output_tokens * OUTPUT_PRICE) / 1_000_000


def rag(query):
    search_results = search(query)
    prompt = build_prompt(query, search_results)
    answer, usage = llm(INSTRUCTIONS, prompt)
    return answer, usage


questions = [
    "I just discovered the course. Can I join now?",
    "How do I get a certificate?",
    "Do I need a GPU for this course?",
    "Can I use Groq instead of OpenAI?",
    "Where do I submit my homework?",
]

lignes = []
for q in questions:
    answer, usage = rag(q)
    lignes.append({
        "question": q,
        "input_tokens": usage.input_tokens,
        "output_tokens": usage.output_tokens,
        "cost": cost(usage),
    })

df_cost = pd.DataFrame(lignes)
print(df_cost)
print(f"Pour 1000 questions : {df_cost['cost'].mean() * 1000:.2f} $")
~~~
