@@ brief
- On range le code du RAG dans deux fichiers, pour ne plus le recopier de notebook en notebook : `ingest.py` (charger la FAQ, construire l'index) et `rag_helper.py` (chercher, construire le prompt, appeler le modèle).
- 🔑 Dans le notebook, `index` et `openai_client` étaient des **variables globales**. Dans un fichier à part, elles n'existent plus. On en fait des **paramètres du constructeur** d'une classe, `RAGBase`. C'est l'**injection de dépendances** : on donne à l'objet ce dont il a besoin au lieu qu'il aille le chercher.
- `index` peut être n'importe quel objet qui a une méthode `search` : minsearch aujourd'hui, sqlitesearch à la leçon suivante. Le reste du code ne change pas.
- 🔑 Une classe se **dérive** : une sous-classe remplace une seule méthode (le prompt, le modèle) et garde toutes les autres.
- `RAGBase.rag(query)` enchaîne `search`, `build_prompt` et `llm`. Les paramètres `instructions`, `prompt_template`, `course` et `model` ont des valeurs par défaut.

@@ predict-answer
`search` **marche** : il renvoie 5 documents. Il n'utilise que `self.index` et `self.course`. Le client n'est utilisé que dans `llm`.

`rag` plante au moment d'appeler le modèle : `AttributeError: 'NoneType' object has no attribute 'responses'`. La recherche et le prompt ont été faits, seul l'appel final échoue.

C'est la force de l'injection de dépendances : tu peux tester chaque pièce séparément, et remplacer le vrai client par un **faux** qui ne coûte rien et répond toujours la même chose. C'est exactement ce que tu vas faire dans l'exercice.

@@ guide
### 1. Récupérer rag_helper.py

Depuis le dossier `mon-travail/module-01/` :

~~~bash
cp /workspaces/llm-zoomcamp/01-agentic-rag/code/rag_helper.py .
~~~

Ton fork contient déjà le code du cours : pas besoin de le télécharger.

### 2. Hériter

`class RAGFr(RAGBase):` crée une sous-classe. Tout ce que tu n'écris pas vient de `RAGBase`. Tu ne réécris que `build_context` et `rag`.

### 3. Le constructeur

Tu veux des instructions françaises **par défaut**, sans recopier les 6 paramètres de `RAGBase`. Prends `**kwargs`, mets ta valeur par défaut avec `kwargs.setdefault("instructions", INSTRUCTIONS_FR)`, puis passe tout au parent avec `super().__init__(index, llm_client, **kwargs)`.

### 4. Le faux client

Le vrai client s'utilise comme `client.responses.create(model=..., input=...)` et renvoie un objet avec `.output_text`. Un faux client n'a besoin que de ça :

~~~python
from types import SimpleNamespace

class FakeResponses:
    def __init__(self):
        self.calls = []
    def create(self, model, input):
        self.calls.append({"model": model, "input": input})
        return SimpleNamespace(output_text="Oui, tu peux encore t'inscrire [1].")

class FakeClient:
    def __init__(self):
        self.responses = FakeResponses()
~~~

Il garde chaque appel dans `calls` : ton test peut vérifier **ce qui a été envoyé**.

### 5. Le vrai essai

Quand le test passe, remplace le faux client par `OpenAI()` et pose une vraie question.

@@ hints
- `SimpleNamespace(output_text="...")` crée un objet qui a un attribut `output_text`, sans écrire de classe.
- `client.responses.calls[0]["input"]` est la liste de messages envoyée : `[0]` est le message `developer`, `[1]` le message `user`.
- Si `rag_fr.py` ne trouve pas `rag_helper`, lance le test depuis le dossier qui contient les deux fichiers.

@@ solution
`rag_fr.py` :

~~~python
from rag_helper import RAGBase

INSTRUCTIONS_FR = """
Tu es l'assistant des étudiants des Zoomcamps de DataTalksClub.
Réponds à la QUESTION en t'appuyant uniquement sur le CONTEXTE, tiré de la FAQ.
Cite les numéros des sources utilisées entre crochets, comme [1].
Si la réponse n'est pas dans le CONTEXTE, réponds « Je ne sais pas. ».
Réponds en français.
""".strip()


class RAGFr(RAGBase):

    def __init__(self, index, llm_client, **kwargs):
        kwargs.setdefault("instructions", INSTRUCTIONS_FR)
        super().__init__(index, llm_client, **kwargs)

    def build_context(self, search_results):
        if not search_results:
            return "Aucun document trouvé."
        lines = []
        for i, doc in enumerate(search_results, start=1):
            lines.append(f"[{i}] {doc['section']}")
            lines.append("Q: " + doc["question"])
            lines.append("A: " + doc["answer"])
            lines.append("")
        return "\n".join(lines).strip()

    def rag(self, query):
        search_results = self.search(query)
        prompt = self.build_prompt(query, search_results)
        answer = self.llm(prompt)
        return {
            "answer": answer,
            "sources": [doc["id"] for doc in search_results],
        }
~~~

client = FakeClient()
assistant = RAGFr(index, client)

@@ breakfix
Écris une sous-classe qui oublie d'appeler le constructeur du parent :

~~~python
class RAGCasse(RAGBase):
    def __init__(self, index, llm_client):
        self.instructions = INSTRUCTIONS_FR

RAGCasse(index, FakeClient()).rag("Can I join?")
~~~

Quelle erreur obtiens-tu ? Pourquoi cite-t-elle cet attribut-là, et pas un autre ?

@@ breakfix-hints
- Quand une sous-classe écrit son propre `__init__`, celui du parent n'est **plus** appelé tout seul.
- Quels attributs `RAGCasse` a-t-il vraiment ? Un seul.
- Regarde l'ordre des lignes de `RAGBase.search` : quel attribut lit-elle en premier ?

@@ breakfix-answer
`AttributeError: 'RAGCasse' object has no attribute 'course'`.

En écrivant son propre `__init__`, `RAGCasse` a **remplacé** celui de `RAGBase`. Python ne l'appelle plus : `self.index`, `self.llm_client`, `self.course` et `self.model` n'existent pas. L'erreur cite `course` parce que c'est le **premier** attribut manquant que le code lit : `search` construit `filter_dict = {"course": self.course}` avant d'utiliser `self.index`.

La réparation : `super().__init__(index, llm_client, instructions=INSTRUCTIONS_FR)`. L'erreur arrive loin de la vraie cause (dans `search`, pas dans `__init__`) : c'est un piège classique de l'héritage.

@@ explain
Pourquoi passer `index` et `llm_client` au constructeur au lieu de les importer dans `rag_helper.py` ? Qu'est-ce que ça te permet de tester ?

@@ cles
- L'injection de dépendances | dependency injection python | On donne à un objet ses outils au lieu qu'il les crée : on peut alors les remplacer, par exemple par un faux pour les tests.
- L'héritage et super() | python inheritance super init | Une sous-classe change une pièce et garde les autres, à condition d'appeler le constructeur du parent.
- Les doublures de test (fakes, mocks) | test doubles fake mock python | Tester un programme qui appelle une API payante sans la payer, et sans dépendre du réseau.
- Le duck typing | python duck typing | « Si ça a une méthode `search`, c'est un index » : c'est ce qui permet de passer de minsearch à sqlitesearch.
