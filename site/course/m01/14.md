@@ brief
- À la leçon 13, un seul aller-retour. Mais on ne sait pas **à l'avance** combien de recherches le modèle voudra faire. Il faut une **boucle** : appeler le modèle, exécuter ses outils, recommencer, jusqu'à ce qu'il réponde sans demander d'outil. Un agent, c'est exactement ça.
- 🔑 Un agent a trois parties : des **instructions** (son rôle, en message `developer`), des **outils** (ici `search`), et une **mémoire** (l'historique des messages, où l'on ajoute chaque sortie du modèle et chaque résultat d'outil).
- `make_call(call)` transforme un `function_call` en `function_call_output` : il lit les arguments JSON, appelle la bonne fonction, et renvoie le résultat avec le `call_id`.
- La condition d'arrêt est la plus simple possible : un tour **sans** appel de fonction, c'est fini. Les frameworks ajoutent des filets de sécurité : un nombre maximal de tours, un budget de tokens, une limite de temps.
- 🔑 Les **instructions pilotent** l'agent : « Make multiple searches » le pousse à chercher plusieurs fois ; « offtopic questions shouldn't be answered » limite son sujet. C'est une forme légère de **garde-fou** (guardrail), pas une garantie.

@@ predict
Regarde la boucle de la leçon : `while True`, et on sort seulement quand le modèle répond sans appeler d'outil. Imagine que le modèle, à cause de tes instructions « Make multiple searches », appelle `search` à **chaque** tour et ne réponde jamais. Que se passe-t-il ? Combien cela coûte-t-il ?

@@ predict-answer
La boucle **ne s'arrête jamais**. Chaque tour est un appel payant, et chaque tour renvoie **tout** l'historique, qui grossit de 5 résultats de recherche à chaque fois. Le coût par tour augmente donc à chaque tour : le prix total grimpe plus vite qu'en ligne droite.

C'est rare avec un bon modèle, mais ça arrive : des instructions trop insistantes, un outil qui renvoie toujours une erreur, une question impossible. C'est pour ça qu'aucun agent en production ne tourne sans **limite de tours**. Le cours le dit en une phrase : limiter à 5 tours et forcer une réponse au dernier. C'est ce que tu vas construire.

@@ practice
Écris une boucle d'agent qu'on peut laisser tourner sans surveillance : elle s'arrête toujours, ne plante pas sur un outil inconnu, et dit ce qu'elle a fait et ce qu'elle a coûté.

@@ constraints
- `agent_loop(instructions, question, max_iterations=5)` renvoie un dictionnaire : `answer`, `iterations`, `tool_calls` (la liste des `(nom, arguments)`), `input_tokens`, `output_tokens`
- Au **dernier** tour, le modèle ne peut plus appeler d'outil (`tool_choice="none"`) : il doit répondre
- `make_call` ne plante jamais : un outil inconnu ou des arguments JSON invalides donnent un `function_call_output` qui contient un message d'erreur
- Les outils sont rangés dans un dictionnaire `{"search": search}` au lieu d'une suite de `if`
- Le test avec un **faux client** : deux recherches puis une réponse, une boucle qui ne s'arrête pas (coupée au 3e tour), un outil inconnu

@@ guide
### 1. Une boucle qui a une fin

Remplace `while True` par `for it in range(1, max_iterations + 1)`. Le `break` reste : on sort plus tôt si le modèle a répondu.

### 2. Forcer la réponse au dernier tour

L'API Responses accepte `tool_choice` : `"auto"` (le modèle choisit) ou `"none"` (interdit d'appeler un outil). Au dernier tour, passe `"none"` : le modèle doit répondre avec ce qu'il a trouvé.

### 3. Un registre d'outils

`tools = {"search": search}` associe un nom à une fonction. `tools.get(call.name)` renvoie la fonction, ou `None` si le nom est inconnu. Ajouter un outil devient une ligne.

### 4. Renvoyer l'erreur au modèle

Si l'outil est inconnu ou si `json.loads` échoue, ne lève pas d'exception : renvoie `{"error": "..."}` comme résultat. Le modèle lit l'erreur au tour suivant et peut se corriger. C'est ce que font tous les frameworks.

### 5. Le faux client scripté

Pour tester sans payer, un faux client renvoie une liste de réponses préparées, une par appel. Les éléments imitent ceux de l'API :

~~~python
from types import SimpleNamespace as NS

def fc(name, args, call_id):
    return NS(type="function_call", name=name, arguments=args, call_id=call_id)

def msg(text):
    return NS(type="message", content=[NS(text=text)])

class Scripted:
    def __init__(self, script):
        self.script = list(script)
        self.calls = []
    def create(self, **kwargs):
        self.calls.append(kwargs)
        out = self.script.pop(0)
        if kwargs.get("tool_choice") == "none":   # un vrai modèle répondrait ici
            out = [msg("forced answer")]
        return NS(output=out, usage=NS(input_tokens=100, output_tokens=10))
~~~

Puis `openai_client = NS(responses=Scripted([...]))`, et ta boucle croit parler au modèle.

@@ hints
- Additionne `response.usage.input_tokens` à **chaque** tour, pas seulement au dernier.
- `answer` peut rester `None` si aucun tour n'a produit de message : ton test du 3e tour forcé vérifie que ça n'arrive pas.
- `sorted(tools)` donne la liste des noms d'outils : mets-la dans le message d'erreur, le modèle saura quoi appeler.

@@ solution
~~~python
import json


def make_call(call, tools):
    try:
        args = json.loads(call.arguments)
    except json.JSONDecodeError as e:
        result = {"error": f"Invalid JSON arguments: {e}"}
    else:
        func = tools.get(call.name)
        if func is None:
            result = {"error": f"Unknown tool {call.name!r}. Available tools: {sorted(tools)}"}
        else:
            result = func(**args)
    return {"type": "function_call_output", "call_id": call.call_id, "output": json.dumps(result)}


def agent_loop(instructions, question, max_iterations=5, model="gpt-5.4-mini"):
    messages = [
        {"role": "developer", "content": instructions},
        {"role": "user", "content": question},
    ]
    tools = {"search": search}
    result = {"answer": None, "iterations": 0, "tool_calls": [], "input_tokens": 0, "output_tokens": 0}

    for it in range(1, max_iterations + 1):
        last = it == max_iterations
        response = openai_client.responses.create(
            model=model,
            input=messages,
            tools=[search_tool],
            tool_choice="none" if last else "auto",   # au dernier tour, il doit répondre
        )
        result["iterations"] = it
        result["input_tokens"] += response.usage.input_tokens
        result["output_tokens"] += response.usage.output_tokens

        messages.extend(response.output)
        has_function_calls = False
        for item in response.output:
            if item.type == "function_call":
                print(f"#{it} {item.name} {item.arguments}")
                result["tool_calls"].append((item.name, item.arguments))
                messages.append(make_call(item, tools))
                has_function_calls = True
            elif item.type == "message":
                result["answer"] = item.content[0].text

        if not has_function_calls:
            break
    return result
~~~

Les trois tests avec le faux client :

~~~python
# 1. Deux recherches, puis une réponse
openai_client = NS(responses=Scripted([
    [fc("search", '{"query": "Olama", "course": "llm-zoomcamp"}', "c1")],
    [fc("search", '{"query": "Ollama", "course": "llm-zoomcamp"}', "c2")],
    [msg("Install Ollama [1]")],
]))
r = agent_loop(instructions, "How do I run Olama locally?")
assert r["iterations"] == 3 and len(r["tool_calls"]) == 2 and r["input_tokens"] == 300

# 2. Un modèle qui ne s'arrête jamais : coupé au 3e tour, avec une réponse forcée
openai_client = NS(responses=Scripted([
    [fc("search", '{"query": "a", "course": "llm-zoomcamp"}', f"c{i}")] for i in range(10)
]))
r = agent_loop(instructions, "q", max_iterations=3)
assert r["iterations"] == 3 and r["answer"] == "forced answer"

# 3. Un outil inconnu et des arguments cassés : pas de plantage
openai_client = NS(responses=Scripted([
    [fc("search_faq", '{"query": "a"}', "c1"), fc("search", "{bad", "c2")],
    [msg("ok")],
]))
r = agent_loop(instructions, "q")
print("Tous les tests passent")
~~~

@@ breakfix-hints

@@ breakfix-answer
`UnboundLocalError: cannot access local variable 'result' where it is not associated with a value`, sur la ligne `result_json = json.dumps(result, indent=2)`.

Le modèle a appelé `search_faq`, le seul nom qu'il connaît. Le `if call.name == "search"` est faux, `result` n'est jamais créé, et la ligne suivante plante. Toute la boucle s'arrête, et tu as payé les appels déjà faits.

Deux leçons. D'abord, le nom dans le schéma et le nom dans ton code doivent **rester alignés** : le cours le dit, et un registre `{"search_faq": search}` rend l'oubli visible. Ensuite, une boucle d'agent ne doit **jamais** planter sur une erreur d'outil : elle renvoie l'erreur au modèle, qui peut se corriger. C'est exactement ce que fait ton `make_call`.

@@ cles
- La boucle agentique | agent loop tool calling while loop | Le cœur de tous les frameworks d'agents : une boucle simple, que tu sais maintenant écrire.
- Les garde-fous (guardrails) | LLM guardrails input output | Empêcher un assistant de sortir de son sujet ou de faire n'importe quoi : les instructions sont le premier niveau, pas le dernier.
- Le registre d'outils | tool registry dispatch dictionary python | Un dictionnaire nom → fonction remplace une chaîne de `if` et rend les erreurs visibles.
- tool_choice | openai tool_choice none auto required | Le levier pour forcer ou interdire les appels d'outils à un tour précis.
