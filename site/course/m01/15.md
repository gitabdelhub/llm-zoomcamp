@@ brief
- La boucle écrite à la main est instructive, mais répétitive. **ToyAIKit**, une petite bibliothèque écrite par le formateur pendant un workshop, l'écrit pour toi. Dans son code, tu retrouves le même `while True`. Attention : c'est un outil d'apprentissage, **pas** de production.
- `Tools()` est le registre d'outils : `agent_tools.add_tool(search, search_tool)` avec ton schéma, ou `add_tool(search)` tout court.
- 🔑 Sans schéma, ToyAIKit le **génère** à partir des **annotations de type** (`query: str`) et de la **docstring**. Tous les frameworks modernes font ce tour : OpenAI Agents SDK, PydanticAI, LangChain, Google ADK.
- `OpenAIResponsesRunner` fait tourner la boucle. `runner.loop(prompt=...)` renvoie un `LoopResult` avec `all_messages` (l'historique), les tokens et `cost`. On passe `previous_messages=result.all_messages` pour **continuer** la conversation.
- Le cours choisit `gpt-5.4-mini` exprès : le modèle par défaut de ToyAIKit suit moins bien les instructions.

@@ verified

@@ guide
### 1. Le deuxième outil

Les sections d'un cours sont dans les documents : un ensemble `{doc["section"] for doc in documents if doc["course"] == course}`, trié. La docstring dit au modèle **quand** l'utiliser : par exemple pour savoir de quoi parle la FAQ d'un cours avant de chercher.

### 2. Lire le schéma généré

`print(json.dumps(agent_tools.get_tools(), indent=2))`. Pour chaque paramètre, compare : le type, la description, s'il est obligatoire, s'il a un `enum`.

### 3. Une question à deux outils

Il faut une question qui demande d'abord une vue d'ensemble, puis un détail. Par exemple : « What topics does the data engineering FAQ cover, and what does it say about Docker? ».

### 4. Regarder ce qu'il a fait

Le `callback` affiche chaque appel d'outil. Compte-les, puis lis `result.cost`.

@@ hints
- Si l'agent n'appelle pas `list_sections`, ta docstring ne dit sans doute pas assez **quand** s'en servir.
- Si `search` cherche dans le mauvais cours, regarde la description générée pour `course` : `"course parameter"` ne dit rien au modèle. C'est une des différences à noter.
- `result.all_messages` est la liste que tu gérais à la main à la leçon 14 : tu peux y compter les `function_call`.

@@ solution
~~~python
import json
from toyaikit.llm import OpenAIClient
from toyaikit.tools import Tools
from toyaikit.chat import IPythonChatInterface
from toyaikit.chat.runners import OpenAIResponsesRunner, DisplayingRunnerCallback


def search(query: str, course: str) -> list[dict]:
    """Search the FAQ of a DataTalksClub course. Call it before answering a course question."""
    return index.search(
        query,
        num_results=5,
        boost_dict={"question": 3.0, "section": 0.5},
        filter_dict={"course": course},
    )


def list_sections(course: str) -> list[str]:
    """List the section names of a course FAQ. Use it to see what the FAQ covers before searching."""
    return sorted({doc["section"] for doc in documents if doc["course"] == course})


agent_tools = Tools()
agent_tools.add_tool(search)
agent_tools.add_tool(list_sections)
print(json.dumps(agent_tools.get_tools(), indent=2))

chat_interface = IPythonChatInterface()
callback = DisplayingRunnerCallback(chat_interface)
runner = OpenAIResponsesRunner(
    tools=agent_tools,
    developer_prompt=instructions,
    chat_interface=chat_interface,
    llm_client=OpenAIClient(model="gpt-5.4-mini"),
)

result = runner.loop(
    prompt="What topics does the data-engineering-zoomcamp FAQ cover, and what does it say about Docker?",
    callback=callback,
)
print(result.cost)
~~~

Les trois différences que tu devrais trouver avec ton schéma de la leçon 13 :

1. `course` n'a plus d'`enum` : le modèle peut écrire un slug qui n'existe pas ;
2. la description de chaque paramètre est générique (`"course parameter"`), au lieu d'expliquer comment le remplir ;
3. les descriptions des outils viennent mot pour mot des docstrings : une docstring vague donne un outil mal utilisé.

C'est le prix de la commodité : le schéma généré est **moins précis** que celui écrit à la main. Les frameworks de production (PydanticAI, OpenAI Agents SDK) savent lire les descriptions des paramètres dans la docstring et les `Literal` : c'est l'une des raisons de les préférer en production.

@@ cles
- Les annotations de type Python | python type hints inspect signature | C'est ce que lisent les frameworks pour décrire tes outils au modèle.
- Les docstrings | python docstring google style args | La docstring devient la description de l'outil : elle s'écrit pour le modèle autant que pour les humains.
- Literal en Python | python typing Literal enum json schema | La façon de dire « seulement ces valeurs » en Python, que certains frameworks traduisent en `enum`.
