@@ brief
- **Embedder** un texte, c'est le transformer en vecteur. L'idée vient de **word2vec** : placer les mots dans un espace où les mots proches par le sens sont proches dans l'espace. Les modèles de phrases font pareil avec une phrase entière, **en tenant compte du contexte** : « judge » n'a pas le même vecteur dans un tribunal et dans « LLM-as-a-judge ».
- On utilise **sentence-transformers** : la bibliothèque tourne sur ta machine, sans coût d'API. Attention, elle installe PyTorch. Le cours ajoute un **index PyTorch CPU** dans `pyproject.toml` pour éviter des gigaoctets de bibliothèques NVIDIA inutiles sans GPU.
- Le modèle **all-MiniLM-L6-v2** : des vecteurs de **384** nombres, rapide sur CPU, bon pour l'anglais. Le premier `SentenceTransformer("all-MiniLM-L6-v2")` télécharge environ 80 Mo depuis HuggingFace.
- `model.encode(texte)` renvoie un tableau numpy de 384 nombres. On ne sait pas lire un nombre seul ; on compare des vecteurs entre eux, avec un **produit scalaire** : `v1.dot(dv)`.
- 🔑 Ce modèle renvoie des vecteurs **normalisés** (de longueur 1). Pour deux vecteurs normalisés, le produit scalaire **est** la similarité cosinus : 1 pour la même direction, 0 pour sans rapport.

### 2. Encoder plusieurs phrases d'un coup

`model.encode(liste)` accepte une liste et renvoie une **matrice** : une ligne par phrase, 384 colonnes. C'est beaucoup plus rapide qu'une boucle.

### 3. Toutes les similarités en une ligne

Si `V` est la matrice (6 lignes, 384 colonnes), `V.dot(V.T)` (ou `V @ V.T`) donne une matrice 6 × 6 : la case `[i, j]` est la similarité entre la phrase `i` et la phrase `j`. La diagonale vaut 1 : chaque phrase est identique à elle-même.

### 4. Vérifier la normalisation

`np.linalg.norm(V, axis=1)` donne la longueur de chaque ligne.

### 5. La plus proche voisine

Pour chaque ligne, la plus grande valeur **hors diagonale**. Une astuce : `np.fill_diagonal(M, -1)` puis `M.argmax(axis=1)`.

@@ hints
- `np.set_printoptions(precision=2, suppress=True)` rend la matrice lisible.
- Des valeurs légèrement négatives (-0,1) sont normales : « sans rapport » donne des valeurs autour de 0, d'un côté ou de l'autre.
- Si ta traduction française se retrouve plus proche d'une phrase sans rapport que de son original, ce n'est pas un bug : c'est la prédiction de cette leçon, en vrai.

@@ solution
~~~python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("all-MiniLM-L6-v2")

phrases = [
    "Can I still join the course after the start date?",       # 0
    "Is it possible to enroll late?",                          # 1 : paraphrase de 0
    "Puis-je encore rejoindre le cours après la date de début ?",  # 2 : traduction de 0
    "How to install Docker on Windows?",                       # 3
    "Docker Desktop does not start on my Windows laptop",      # 4 : proche de 3
    "Where do I submit my homework?",                          # 5 : sans rapport
]

V = model.encode(phrases)
print(V.shape)                              # (6, 384)
print(np.linalg.norm(V, axis=1))            # des 1 : les vecteurs sont normalisés

np.set_printoptions(precision=2, suppress=True)
M = V @ V.T
print(M)

M2 = M.copy()
np.fill_diagonal(M2, -1)
for i, j in enumerate(M2.argmax(axis=1)):
    print(f"{i} → {j} ({M[i, j]:.2f})")
~~~

@@ breakfix-hints
- Regarde `model.max_seq_length`.
- Un modèle ne lit pas des caractères, il lit des **tokens**. Combien de tokens a le texte long ? `len(model.tokenizer(long)["input_ids"])`.
- Où se trouve la phrase ajoutée : au début ou à la fin du texte ?

@@ breakfix-answer
Pour le texte long, la similarité vaut **1,0** : l'ajout n'a rien changé. Pour la phrase courte, elle tombe autour de 0,78.

all-MiniLM-L6-v2 ne lit que les **256 premiers tokens** (`model.max_seq_length` vaut 256). Tout ce qui vient après est **coupé sans prévenir**. La phrase ajoutée à la fin d'un long texte est invisible pour le modèle, donc pour la recherche.

C'est un piège réel : sur ma copie de la FAQ, plus de 300 documents dépassent 256 tokens. Si la réponse à une question se trouve à la fin d'une longue entrée, la recherche vectorielle ne la verra jamais. C'est l'une des raisons du **découpage en morceaux** (chunking), que tu as vu dans le homework 1.
