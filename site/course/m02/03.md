@@ brief
- On reprend `load_faq_data()` du module 1 et on construit **un texte par document** : `question + " " + answer`. Une question pourra ainsi trouver un document par sa question ou par sa réponse.
- On encode par **lots** (batches) de 50 textes, avec `tqdm` pour voir la progression. Tout encoder d'un coup marche aussi, mais on ne voit rien avancer, et un lot qui plante est plus facile à retrouver.
- On empile les vecteurs dans une **matrice** `X = np.array(vectors)` : une ligne par document, 384 colonnes. `X.shape` vaut environ `(1208, 384)` dans le cours.
- 🔑 C'est l'étape **lente** du vectoriel : un réseau de neurones tourne sur chaque document. Sans GPU, dans un Codespace, compte une minute environ. On ne veut la payer qu'une fois.

@@ practice
Calcule les embeddings une seule fois, **enregistre-les sur le disque**, et mesure ce que le modèle ne voit pas.

@@ constraints
- Les embeddings de toute la FAQ, par lots de 50, avec le temps total affiché
- La matrice `X` enregistrée dans `X.npy`, et les `id` des documents dans le même ordre dans `ids.json`
- Au redémarrage du notebook, si `X.npy` existe, on le recharge au lieu de recalculer
- Le nombre de documents qui dépassent 256 tokens, et le pourcentage que ça représente
- `X.npy` n'est pas commité

@@ guide
### 1. Mesurer le temps

`time.perf_counter()` avant et après la boucle de la leçon.

### 2. Enregistrer

`np.save("X.npy", X)` écrit la matrice dans un fichier binaire ; `np.load("X.npy")` la relit en une fraction de seconde. Les `id` vont à côté, en JSON : la ligne `i` de `X` correspond au document `ids[i]`. Sans eux, impossible de savoir à quel document appartient un vecteur si la FAQ change.

### 3. Ne pas recalculer

`from pathlib import Path`, puis `if Path("X.npy").exists(): ... else: ...`. Vérifie aussi que les `id` enregistrés correspondent aux documents chargés : si la FAQ a changé, il faut recalculer.

### 4. Compter les tokens

`model.tokenizer` est le tokenizer du modèle. `len(model.tokenizer(texte)["input_ids"])` compte les tokens d'un texte, sans couper.

### 5. Le .gitignore

Ajoute `*.npy` au `.gitignore` de `mon-travail/module-02/`.

@@ hints
- `X.dtype` vaut `float32` : 4 octets par nombre. 1500 documents × 384 nombres × 4 octets, c'est un peu plus de 2 Mo.
- Si les `id` ne correspondent plus (`ids != [d["id"] for d in documents]`), recalcule : c'est ce qu'on appelle une **invalidation de cache**.
- Le tokenizer peut afficher un avertissement sur les textes trop longs : c'est justement ce que tu mesures.

@@ solution
~~~python
import json
import time
from pathlib import Path

import numpy as np
from tqdm.auto import tqdm
from sentence_transformers import SentenceTransformer

from ingest import load_faq_data

model = SentenceTransformer("all-MiniLM-L6-v2")
documents = load_faq_data()
texts = [doc["question"] + " " + doc["answer"] for doc in documents]
ids = [doc["id"] for doc in documents]

if Path("X.npy").exists() and json.loads(Path("ids.json").read_text()) == ids:
    X = np.load("X.npy")
    print("Embeddings rechargés depuis le disque")
else:
    start = time.perf_counter()
    vectors = []
    for i in tqdm(range(0, len(texts), 50)):
        vectors.extend(model.encode(texts[i:i + 50]))
    X = np.array(vectors)
    np.save("X.npy", X)
    Path("ids.json").write_text(json.dumps(ids))
    print(f"Embeddings calculés en {time.perf_counter() - start:.0f} s")

print(X.shape, X.dtype)

lengths = [len(model.tokenizer(t)["input_ids"]) for t in texts]
trop_longs = sum(n > model.max_seq_length for n in lengths)
print(f"{trop_longs} documents dépassent {model.max_seq_length} tokens ({trop_longs / len(texts):.0%})")
~~~

Sur ma copie de la FAQ : environ 35 secondes, une matrice `(1470, 384)` en `float32`, et 322 documents trop longs, soit 22 %.
