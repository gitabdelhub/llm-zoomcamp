@@ brief
- On embedde la question avec **le même modèle**, puis `scores = X.dot(v_query)` : une multiplication matrice-vecteur donne **un score par document**, la similarité cosinus avec la question.
- La même chose avec une boucle Python marche aussi, mais numpy exécute du code C optimisé : la version matricielle est bien plus rapide.
- `np.argmax(scores)` donne le meilleur document. `np.argsort(-scores)[:5]` donne les 5 meilleurs, du plus proche au moins proche : on trie les scores **négatifs**, ce qui transforme un tri croissant en tri décroissant.
- 🔑 On renvoie **5** résultats et pas un seul : la réponse peut être répartie sur plusieurs documents, et le bon n'est pas toujours premier. Le chiffre 5 est un choix au jugé : au module 4, tu mesureras si 3 ou 10 marchent mieux.
- C'est une recherche **exacte** (on compare la question à tous les documents) : parfait pour un petit jeu de données, trop lent pour des millions.

@@ guide
### 1. Filtrer avec un masque

`courses = np.array([d["course"] for d in documents])` une fois pour toutes. Puis `idx = np.where(courses == course)[0]` donne les numéros des documents du cours. Tu ne calcules les scores que pour eux : `X[idx].dot(v)`.

### 2. Trier et revenir aux documents

`order = np.argsort(-scores)[:num_results]` donne des positions **dans `idx`**, pas dans `documents`. Le document est `documents[idx[i]]`. C'est l'erreur classique de cette fonction.

### 3. Comparer avec la recherche lexicale

Reconstruis l'index minsearch du module 1 (`Index(text_fields=[...], keyword_fields=["course"])`). Pour chaque requête, cherche la **position** de la bonne entrée dans les deux listes de résultats (par son `id`), ou « absente » si elle n'est pas dans le top 5.

### 4. Choisir les requêtes

Prends les deux de la prédiction, une question tournée autrement, et une requête faite d'un **terme exact** rare, comme un message d'erreur ou un nom d'outil : c'est là que la recherche lexicale brille.

@@ hints
- `np.where(courses == course)[0]` : le `[0]` est nécessaire, `np.where` renvoie un tuple.
- Pour trouver la position d'un `id` : `next((i for i, d in enumerate(results) if d["id"] == target), None)`.
- Un terme exact qui marche bien en lexical : un nom de fonction ou un message d'erreur copié tel quel, comme `model_decommissioned` ou `RateLimitError`.

~~~python
import numpy as np
from minsearch import Index

courses = np.array([d["course"] for d in documents])
COURSES = set(courses)


def vector_search(query, course="llm-zoomcamp", num_results=5):
    if course not in COURSES:
        raise ValueError(f"Cours inconnu : {course!r}")
    v = model.encode(query)
    idx = np.where(courses == course)[0]        # les documents du cours
    scores = X[idx].dot(v)                      # un score par document du cours
    order = np.argsort(-scores)[:num_results]   # des positions dans idx
    return [(float(scores[i]), documents[idx[i]]) for i in order]


text_index = Index(text_fields=["question", "section", "answer"], keyword_fields=["course"])
text_index.fit(documents)


def text_search(query, course="llm-zoomcamp", num_results=5):
    return text_index.search(query, boost_dict={"question": 2.0, "section": 0.5},
                             filter_dict={"course": course}, num_results=num_results)


def rank(results, target_id):
    return next((i + 1 for i, d in enumerate(results) if d["id"] == target_id), "absente")


join_id = next(d["id"] for d in documents
               if d["course"] == "llm-zoomcamp" and d["question"].startswith("I just discovered the course"))
ollama_id = next(d["id"] for d in documents if d["question"] == "Ollama: How to install Ollama?")

tests = [
    ("Is it possible to enroll late?", join_id),
    ("How do I run Olama locally?", ollama_id),
    ("the program has already begun, can I still sign up?", join_id),
    ("ollama install", ollama_id),
]
for q, target in tests:
    lex = rank(text_search(q), target)
    vec = rank([d for _, d in vector_search(q)], target)
    print(f"{q[:45]:45} lexical : {lex}   vectoriel : {vec}")
~~~

@@ breakfix-answer
`ValueError: shapes (1470,384) and (1,384) not aligned: 384 (dim 1) != 1 (dim 0)`.

Avec une liste, `encode` renvoie une **matrice** d'une ligne, de forme `(1, 384)`, et non un vecteur `(384,)`. Pour `X.dot(v)`, numpy veut que la dernière dimension de `X` (384) soit égale à la première de `v` (ici 1).

Deux réparations : `model.encode("texte")` sans liste, ou `v[0]`. Le réflexe à prendre : quand numpy parle de `shapes`, affiche le `.shape` de chaque côté. La moitié des bugs de vectoriel sont des problèmes de forme.
