@@ brief
- Le RAG du module 1 a trois étapes : chercher, construire le prompt, appeler le modèle. Passer au vectoriel ne touche **que** la recherche.
- `RAGBase` attend un index qu'on interroge avec le **texte** de la question. `VectorSearch` veut un **vecteur**. On dérive donc `RAGBase` en `RAGVector`, qui reçoit en plus un `embedder` et remplace **une seule** méthode : `search`.
- `RAGVector.search` encode la question, puis appelle `self.index.search(query_vector, num_results=..., filter_dict=...)`. Tout le reste (le prompt, l'appel au modèle) est hérité.
- 🔑 C'est le bénéfice de la classe du module 1 : changer de moteur de recherche, c'est changer une méthode. Le même geste permettra plus tard de changer de fournisseur de LLM en remplaçant seulement `llm`.

Tu ne dérives pas : tu passes directement l'index vectoriel à la classe du module 1, `RAGBase(index=vindex, llm_client=openai_client)`, puis tu appelles `.rag("Can I join?")`. Que se passe-t-il ?

@@ predict-answer
Ça plante, mais **pas** là où on l'attendrait : `TypeError: VectorSearch.search() got an unexpected keyword argument 'boost_dict'`.

`RAGBase.search` appelle `self.index.search(query, num_results=..., boost_dict=..., filter_dict=...)`. Les deux index ont une méthode `search`, mais pas les mêmes paramètres : `VectorSearch` ne connaît pas `boost_dict` (on ne « booste » pas un champ dans un vecteur), et il attend un vecteur au lieu du texte. Python refuse au premier paramètre inconnu.

Le duck typing du module 1 (« s'il a une méthode `search`, c'est un index ») a ses limites : deux objets peuvent avoir le même nom de méthode et un contrat différent. C'est pour ça que `RAGVector` remplace `search`.

@@ guide
### 1. Pourquoi pas VectorSearch ici

`VectorSearch` ne renvoie pas les scores (leçon 5). Ta classe fait donc sa recherche avec numpy, comme ta fonction de la leçon 4.

### 2. Le constructeur

`def __init__(self, embedder, X, documents, min_score=0.3, **kwargs)`, puis `super().__init__(index=None, **kwargs)` : ta classe n'utilise pas `self.index`, mais `RAGBase` attend ce paramètre.

### 3. Choisir le seuil

Sur ma copie de la FAQ, les questions hors sujet (« what's queen gambit? », « How do I cook salmon? ») ont un meilleur score entre 0,14 et 0,20, et les vraies questions du cours entre 0,37 et 0,55. 0,3 sépare les deux. Vérifie sur tes propres questions : un seuil se mesure, il ne se devine pas.

### 4. Le contexte vide

Remplace `build_context` : si la liste est vide, renvoie `No documents found.`. C'est la règle de la leçon 6 du module 1.

### 5. Le faux client

Le `FakeClient` de la leçon 8 du module 1 garde ce qu'il reçoit dans `calls` : regarde le message `user` envoyé pour chaque question.

@@ hints
- `np.where(courses == self.course)[0]` donne les documents du cours ; tu filtres ensuite les scores avec `scores[order] >= self.min_score`.
- « Do I need a GPU? » a un meilleur score de 0,18 dans le cours LLM sur ma copie : il n'y a simplement pas d'entrée sur le sujet. « I don't know » est alors la **bonne** réponse.
- Le seuil dépend du modèle : avec un autre modèle d'embeddings, les scores changent d'échelle, et le seuil aussi.

@@ solution
~~~python
import numpy as np
from types import SimpleNamespace
from rag_helper import RAGBase


class RAGVectorSeuil(RAGBase):

    def __init__(self, embedder, X, documents, min_score=0.3, **kwargs):
        super().__init__(index=None, **kwargs)
        self.embedder = embedder
        self.X = X
        self.documents = documents
        self.min_score = min_score
        self.courses = np.array([d["course"] for d in documents])

    def search(self, query, num_results=5):
        v = self.embedder.encode(query)
        idx = np.where(self.courses == self.course)[0]
        scores = self.X[idx].dot(v)
        order = np.argsort(-scores)[:num_results]
        return [self.documents[idx[i]] for i in order if scores[i] >= self.min_score]

    def build_context(self, search_results):
        if not search_results:
            return "No documents found."
        return super().build_context(search_results)


class FakeResponses:
    def __init__(self):
        self.calls = []
    def create(self, model, input):
        self.calls.append(input)
        return SimpleNamespace(output_text="(réponse du faux modèle)")


fake = SimpleNamespace(responses=FakeResponses())
assistant = RAGVectorSeuil(embedder=model, X=X, documents=documents, llm_client=fake)

assistant.rag("what's queen gambit?")
assert "No documents found." in fake.responses.calls[-1][1]["content"]

assistant.rag("the program has already begun, can I still sign up?")
assert "Can I still join?" in fake.responses.calls[-1][1]["content"]
print("Tous les tests passent")
~~~

@@ breakfix-hints

- Que fait l'index texte en premier avec une requête ? Il la met en minuscules.
- L'erreur parle d'un `numpy.ndarray` : d'où vient-il ?

@@ breakfix-answer
`AttributeError: 'numpy.ndarray' object has no attribute 'lower'`.

`RAGVector` encode la question et passe le **vecteur** à `index.search`. L'index texte, lui, veut un texte : sa première opération est `query.lower()`, qui n'existe pas pour un tableau numpy.

Le message ne dit pas « mauvais index ». Il dit seulement qu'un tableau n'a pas de méthode `lower`. Pour remonter à la cause, il faut savoir quel objet a reçu quoi. Deux réflexes : des noms qui disent ce qu'ils contiennent (`text_index`, `vector_index`), et une vérification au constructeur, par exemple `isinstance(index, VectorSearch)`.

@@ cles
- Le seuil de similarité | similarity threshold vector search RAG | Savoir dire « je n'ai rien trouvé » au lieu d'envoyer au modèle les moins mauvais documents.
- Le principe ouvert/fermé | open closed principle python inheritance | Étendre un comportement sans modifier le code existant, comme `RAGVector` avec `RAGBase`.
- Le contrat d'une interface | interface contract duck typing limits | Même nom de méthode ne veut pas dire mêmes paramètres.
