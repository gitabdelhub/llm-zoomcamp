@@ brief
- minsearch a trois limites, qu'on ne sentait pas avec le texte : il **recalcule** l'index à chaque démarrage (une minute d'embeddings), il garde tout **en mémoire**, et il compare la question à **tous** les documents.
- Comparer à tout, c'est la recherche **exacte** (NN). Au-delà de 10 000 documents environ, ça devient lent. La recherche **approximative** (ANN) réduit d'abord à une région de candidats probables, puis ne calcule les scores que dans cette région. Elle peut rater le meilleur document, mais elle est beaucoup plus rapide.
- **sqlitesearch** (déjà vu au module 1 pour le texte) a une classe `VectorSearchIndex` : les vecteurs sont stockés dans un fichier SQLite, et la recherche se fait en deux temps, des candidats approximatifs puis un tri exact par similarité cosinus.
- Trois modes ANN : `lsh` (projections aléatoires), `ivf` (des groupes de vecteurs, par k-means), `hnsw` (un graphe de voisins, le meilleur rappel).
- 🔑 Le gain principal ici, c'est la **séparation en deux processus** : un script d'ingestion calcule les embeddings une fois et remplit le fichier, l'application se contente de rouvrir l'index. Elle démarre instantanément.

@@ guide
### 1. Savoir si l'index est déjà rempli

`VectorSearchIndex` a une méthode `count()`, qui renvoie le nombre de documents déjà dans le fichier. Rouvre l'index, compare `vs_index.count()` à `len(documents)`.

### 2. Les trois cas

- Le compte est bon : on ne fait rien.
- L'index est vide : `fit`.
- L'index est rempli, mais pas avec le bon nombre (la FAQ a changé) : `vs_index.clear()`, puis `fit`.

### 3. Le rappel@5

Pour une question : `vrai = set(ids[np.argsort(-X.dot(q))[:5]])` (la recherche exacte), `trouve = {r["id"] for r in vs_index.search(q, num_results=5)}`. Le rappel, c'est `len(vrai & trouve) / 5`. Fais la moyenne sur tes 10 questions.

### 4. Un fichier par mode

Chaque mode dans son propre fichier (`v_lsh.db`, `v_ivf.db`, `v_hnsw.db`), supprimé avant de mesurer, sinon tu tombes sur l'erreur de `fit` des faits vérifiés.

@@ hints
- `ids = np.array([d["id"] for d in documents])` permet d'indexer les `id` avec le résultat de `argsort`.
- Le mode `lsh` a un paramètre `n_tables` (8 par défaut) : plus de tables, plus de chances de trouver les bons voisins. Avec 16, j'ai obtenu 0,70 au lieu de 0,50.
- Pour mesurer le temps : `time.perf_counter()` avant et après `fit`.
- Compter les documents n'est pas une vérification parfaite : si une entrée de la FAQ change sans que leur nombre change, le script ne le voit pas. Comparer les `id`, comme à la leçon 3, est plus sûr.

~~~python
# ingest_vectors.py
import json
from pathlib import Path

import numpy as np
from sentence_transformers import SentenceTransformer
from sqlitesearch import VectorSearchIndex

from ingest import load_faq_data

documents = load_faq_data()
ids = [d["id"] for d in documents]

vs_index = VectorSearchIndex(keyword_fields=["course"], mode="ivf", db_path="faq_vectors2.db")

if vs_index.count() == len(documents):
    print(f"Index déjà à jour ({len(documents)} documents), rien à faire")
else:
    if vs_index.count() > 0:
        vs_index.clear()
    if Path("X.npy").exists() and json.loads(Path("ids.json").read_text()) == ids:
        X = np.load("X.npy")
    else:
        model = SentenceTransformer("all-MiniLM-L6-v2")
        X = model.encode([d["question"] + " " + d["answer"] for d in documents], batch_size=50, show_progress_bar=True)
    vs_index.fit(X, documents)
    print(f"{vs_index.count()} documents indexés")

vs_index.close()
~~~

~~~python
# Dans le notebook : le compromis des trois modes
import os, time
import numpy as np
from sqlitesearch import VectorSearchIndex

questions = [
    "Can I still join the course after the start date?", "How do I run Ollama locally?",
    "Where do I submit my homework?", "Do I need a GPU?", "How do I get a certificate?",
    "Docker permission denied", "What is the leaderboard?", "How much does OpenAI cost?",
    "Can I use Groq?", "How do I install uv?",
]
Q = model.encode(questions)
ids = np.array([d["id"] for d in documents])
exact = [set(ids[np.argsort(-X.dot(q))[:5]]) for q in Q]

for mode in ["lsh", "ivf", "hnsw"]:
    path = f"v_{mode}.db"
    if os.path.exists(path):
        os.remove(path)
    ix = VectorSearchIndex(keyword_fields=["course"], mode=mode, db_path=path)
    start = time.perf_counter()
    ix.fit(X, documents)
    duree = time.perf_counter() - start
    rappel = np.mean([len({r["id"] for r in ix.search(q, num_results=5)} & e) / 5 for q, e in zip(Q, exact)])
    print(f"{mode:5} rappel@5 {rappel:.2f}   fit {duree:.1f} s")
    ix.close()
~~~

@@ breakfix-answer
La recherche plante avec une erreur numpy : `ValueError: matmul: Input operand 0 does not have enough dimensions…`.

Chaque mode range dans le fichier ses propres structures : `ivf` y enregistre des centres de groupes, `lsh` cherche des plans de projection. Rouvert en `lsh`, l'index lit des données qui n'existent pas sous la forme attendue, et le calcul matriciel échoue. Le message parle de dimensions, pas de mode.

La leçon à retenir : l'ingestion et l'application partagent un **contrat** (le modèle d'embeddings, le mode, le chemin du fichier). Écris-le à un seul endroit, un petit `config.py` importé par les deux scripts, au lieu de le recopier.
