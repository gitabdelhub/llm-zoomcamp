# Un agent dans une tâche Airflow

Au module 1, tu as écrit la boucle d'un agent à la main : appeler le modèle, exécuter les outils qu'il demande, lui renvoyer les résultats, recommencer jusqu'à ce qu'il réponde sans outil. Puis, dans le défi, tu en as fait une petite bibliothèque : `agentkit.py`, avec `tool_schema` et `Agent`.

Dans Kestra, une tâche `AIAgent` fait cette boucle pour toi. Dans Airflow, il n'y a pas besoin d'un opérateur spécial : **une tâche `@task` est une fonction Python**, et ta boucle tient dans une fonction. L'agent devient une étape d'un DAG, avec tout ce qu'Airflow apporte autour : les paramètres, les relances, une limite de temps, les logs et l'historique.

## Un DAG ou un agent ?

| Un DAG classique | Un agent |
| --- | --- |
| Les étapes sont écrites à l'avance | Le modèle choisit les étapes |
| Même entrée, même chemin | Le chemin change selon ce que le modèle trouve |
| Audit simple, coût prévisible | Plus souple, coût variable |

Utilise un agent quand tu ne connais pas les étapes à l'avance. Garde un DAG classique quand elles sont fixes, quand il faut pouvoir les auditer, ou quand le coût doit rester prévisible. Et souvent, le bon choix, c'est **les deux** : un DAG fixe, dont **une** tâche est un agent.

## Deux exemples, comme dans le cours officiel

**`simple_agent`** refait le flow `4_simple_agent` du cours : deux appels au modèle enchaînés. `multilingual_agent` résume un texte, avec une longueur (`short`, `medium`, `long`) et une langue choisies en paramètres ; `english_brevity` résume ce résumé en une phrase anglaise ; `log_token_usage` affiche les tokens de chacun. Kestra évite de répéter la configuration du modèle avec `pluginDefaults` ; en Python, c'est une fonction `llm()` commune et un dictionnaire `default_args` pour les relances.

**`faq_agent`** est un vrai agent : il a un outil, `search_faq`, qui cherche dans pgvector, et il décide combien de fois l'appeler. Sa tâche suivante enregistre un rapport en Markdown dans `data/reports/` : la réponse, les recherches faites, les tokens. Le cours officiel le fait avec un outil « fichier » donné à l'agent ; ici, c'est une tâche fixe après l'agent. Écrire le rapport n'est pas une décision : ce n'est pas au modèle de la prendre.

## 🔑 Ce qu'Airflow ajoute autour de la boucle

- `execution_timeout=timedelta(minutes=5)` : un agent qui tourne trop longtemps est arrêté.
- `max_iterations` en **paramètre** du DAG : tu peux le baisser pour un essai sans toucher au code.
- Les **relances** pour les erreurs passagères de l'API.
- L'**historique** : chaque run garde ses logs, son rapport et ses tokens.

@@ guide
### 1. La boîte à outils

Copie ton `agentkit.py` du défi 1 dans `dags/`. S'il passe les dix vérifications du défi, il est prêt. Sinon, la solution du défi 1 marche.

### 2. L'outil

`search_faq(query: str, course: str = "llm-zoomcamp") -> list`, avec une docstring au format `Args:` : c'est ce que `tool_schema` lit pour écrire la description de l'outil. Dedans, le code de `retrieve` de la leçon 5.

Les imports (`openai`, `agentkit`) dans la fonction. `Agent(OpenAI(), INSTRUCTIONS, tools=[search_faq], max_iterations=params["max_iterations"])`, puis `run`. La tâche renvoie le dictionnaire de `run` : il est petit, il passe dans XCom.

`run_id` contient des `:` et des `+`. Remplace ce qui n'est ni une lettre, ni un chiffre, ni `-` ou `_` avant d'en faire un nom de fichier.

### 5. Les trois essais

Lance-les depuis le formulaire Trigger. Compare les trois rapports : le nombre de recherches, les tokens, et ce que répond l'agent quand il n'a plus le droit de chercher.

@@ hints

@@ solution
~~~python
"""Un agent de recherche sur la FAQ, dans une tâche Airflow : la boîte à outils du défi du module 1."""
import os
from datetime import datetime, timedelta
from pathlib import Path

from airflow.sdk import Connection, Param, dag, task

MODEL_DIR = os.environ.get("EMBED_MODEL_DIR", "/opt/airflow/models/Xenova/all-MiniLM-L6-v2")
DATA_DIR = Path(os.environ.get("FAQ_DATA_DIR", "/opt/airflow/data"))

INSTRUCTIONS = """You're a teaching assistant for the LLM Zoomcamp.
Use the search_faq tool, as many times as needed, before answering. Answer only from what you found.
If the FAQ doesn't have the answer, say so."""


def search_faq(query: str, course: str = "llm-zoomcamp") -> list:
    """Search the FAQ of a DataTalksClub course.

    Args:
        query: Search keywords in English.
        course: The course slug.
    """
    import psycopg
    from embedder import Embedder
    embed = Embedder(MODEL_DIR)
    embed.tokenizer.enable_truncation(256)
    v = "[" + ",".join(str(float(x)) for x in embed.encode(query)) + "]"
    with psycopg.connect(Connection.get("pgvector").get_uri()) as conn:
        rows = conn.execute("SELECT question, answer FROM documents WHERE course = %s "
                            "ORDER BY embedding <=> %s::vector LIMIT 5", (course, v)).fetchall()
    return [{"question": q, "answer": a} for q, a in rows]


@dag(schedule=None, start_date=datetime(2026, 11, 1), catchup=False,
     default_args={"retries": 2, "retry_delay": timedelta(seconds=20), "retry_exponential_backoff": True,
                   "execution_timeout": timedelta(minutes=5)},
     params={"question": Param("How do I run Ollama on my laptop?", type="string", minLength=3),
             "max_iterations": Param(5, type="integer", minimum=1, maximum=10)},
     tags=["llm-zoomcamp", "agents"])
def faq_agent():

    @task
    def agent(params=None):
        from openai import OpenAI
        from agentkit import Agent
        bot = Agent(OpenAI(), INSTRUCTIONS, tools=[search_faq], max_iterations=params["max_iterations"])
        result = bot.run(params["question"])
        print(f"{result['iterations']} appels au modèle, {len(result['tool_calls'])} recherches, "
              f"{result['input_tokens']} + {result['output_tokens']} tokens")
        return result

    @task
    def save_report(result, params=None, run_id=None):
        safe = "".join(c if c.isalnum() or c in "-_" else "_" for c in run_id)
        path = DATA_DIR / "reports" / f"{safe}.md"
        path.parent.mkdir(parents=True, exist_ok=True)
        searches = "\n".join(f"- `{name}` {args}" for name, args in result["tool_calls"]) or "- aucune"
        path.write_text(f"# {params['question']}\n\n{result['answer']}\n\n## Recherches\n\n{searches}\n\n"
                        f"{result['iterations']} appels au modèle, "
                        f"{result['input_tokens']} tokens en entrée, {result['output_tokens']} en sortie\n")
        return str(path)

    save_report(agent())


faq_agent()
~~~

- Les relances d'Airflow se déclenchent quand une tâche **lève** une exception. Est-ce que `agent` en lève une ?

@@ breakfix-answer
Le run est **vert**. Ton `Agent` attrape l'erreur de l'outil et l'envoie au modèle sous la forme `{"error": "OperationalError: connection failed: connection to server at ... failed: Connection refused"}`. Le modèle répond qu'il n'a pas pu chercher, la tâche réussit, et Airflow ne relance rien. Dans mon essai, les tokens d'entrée sont passés de 1557 à 253 : l'outil n'a renvoyé qu'un message d'erreur.

La robustesse du défi 1 est bonne pour les erreurs que le **modèle** peut corriger : un argument invalide, un cours mal écrit. Elle est mauvaise pour une panne d'**infrastructure** : la base est éteinte, le modèle n'y peut rien, et le run vert cache la panne. La réparation : dans `search_faq`, laisse passer les erreurs de connexion (ou relève-les dans la tâche quand un outil a échoué pour cette raison), pour que la tâche échoue et que les relances d'Airflow fassent leur travail.
