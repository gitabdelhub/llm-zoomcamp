- Depuis le module 1, on donnait un boost de 3,0 à `question`, parce que « une question ressemble à la question de la FAQ ». C'était une **intuition**. Maintenant, on la teste : on change un paramètre, on relance `evaluate` sur les mêmes questions, on compare.
- Le boost de `question` seul : la meilleure valeur est **1,0**, pas de boost du tout. Augmenter le boost **fait baisser** les deux métriques.
- Une petite **recherche par grille** (grid search) sur les trois boosts : la meilleure combinaison donne deux fois plus de poids à `answer` qu'à `question`, et presque rien à `section`. Hit rate 0,975, MRR 0,885, contre 0,899 et 0,769 au départ.
- 🔑 Seules les **proportions** comptent : 1 : 2 : 0,1 et 5 : 10 : 0,5 donnent exactement le même classement. Le cours garde les plus petits nombres, plus lisibles.
- Une grille, c'est bien pour quelques paramètres. Au-delà : des combinaisons au hasard, ou l'optimisation bayésienne (hyperopt). Et le cours le dit en une ligne : garde une **partie des questions de côté**, pour ne pas sur-ajuster le jeu d'évaluation. C'est l'exercice de cette leçon.
- Plus de résultats (top 10) fait monter le hit rate, mais envoie plus de contexte au LLM : plus cher, et plus difficile pour lui de trouver ce qui compte.

@@ practice

@@ constraints
- Un découpage **par document** : les 5 questions d'un même document vont toutes du même côté, 20 % des documents mis de côté, avec une graine fixe
- La grille de la leçon (3 × 4 × 3 = 36 combinaisons), évaluée uniquement sur la partie de réglage
- Le MRR des boosts de départ et de la meilleure grille, sur la partie de réglage **et** sur la partie mise de côté : un tableau de 2 × 2
- Une phrase qui explique pourquoi on coupe par document et pas par question
- Le test qui montre que 1 : 2 : 0,1 et 2 : 4 : 0,2 donnent les mêmes classements, question par question

@@ guide
### 1. Couper par document

La liste triée des `id` de document, mélangée avec `random.Random(42).shuffle(ids)`. Les 20 premiers pour cent vont de côté. Une question va du côté de son document.

### 2. La grille, sur une partie

La boucle de la leçon, mais `evaluate(train, ...)` au lieu de `evaluate(ground_truth, ...)`. Garde le meilleur MRR.

### 3. Le tableau

Les boosts de départ (`question` 3,0, `section` 0,5) et la meilleure grille, chacun évalué sur `train` et sur `test`.

### 4. Les proportions

Pour chaque question, compare la liste des `id` renvoyés avec les deux jeux de boosts. Si toutes les listes sont égales, les deux réglages sont une seule recherche.

@@ hints
- Pourquoi pas par question ? Les 5 questions d'un document se ressemblent : si quatre sont dans la partie de réglage et une de côté, la grille a déjà « vu » la réponse de celle-ci.
- `random.Random(42)` crée un générateur à part, avec sa propre graine : ton découpage ne change pas si une autre cellule utilise `random`.
- minsearch multiplie le score de chaque champ par son boost, puis additionne : multiplier tous les boosts par 2 multiplie chaque score total par 2, sans changer l'ordre.

@@ solution
~~~python
import json
import random

import pandas as pd

from ingest import build_index

ground_truth = pd.read_csv("data/ground_truth-new.csv").to_dict(orient="records")
documents = json.load(open("/workspaces/llm-zoomcamp/site/data/faq-llm-2026-05-12.json"))
index = build_index(documents)


def search_boosts(query, boosts):
    return index.search(query, num_results=5, boost_dict=boosts)


def evaluate(questions, boosts):
    rel = [[int(d["id"] == q["document"]) for d in search_boosts(q["question"], boosts)] for q in questions]
    hit = sum(1 for line in rel if 1 in line) / len(rel)
    mrr = sum(1 / (line.index(1) + 1) for line in rel if 1 in line) / len(rel)
    return {"hit_rate": hit, "mrr": mrr}


ids = sorted({q["document"] for q in ground_truth})
random.Random(42).shuffle(ids)
test_ids = set(ids[: len(ids) // 5])
train = [q for q in ground_truth if q["document"] not in test_ids]
test = [q for q in ground_truth if q["document"] in test_ids]
print(len(train), "questions pour régler,", len(test), "mises de côté")

grid = [{"question": a, "answer": b, "section": c}
        for a in (1.0, 2.0, 5.0) for b in (1.0, 2.0, 4.0, 10.0) for c in (0.1, 0.2, 0.5)]
best = max(grid, key=lambda boosts: evaluate(train, boosts)["mrr"])
start = {"question": 3.0, "section": 0.5}
table = pd.DataFrame({
    "réglage": [evaluate(train, start)["mrr"], evaluate(train, best)["mrr"]],
    "de côté": [evaluate(test, start)["mrr"], evaluate(test, best)["mrr"]],
}, index=["départ", "grille {question} : {answer} : {section}".format(**best)])
print(table.round(3))

same = all(
    [d["id"] for d in search_boosts(q["question"], {"question": 1.0, "answer": 2.0, "section": 0.1})]
    == [d["id"] for d in search_boosts(q["question"], {"question": 2.0, "answer": 4.0, "section": 0.2})]
    for q in ground_truth)
print("1 : 2 : 0,1 et 2 : 4 : 0,2 donnent les mêmes classements :", same)
~~~

@@ cles
- La recherche par grille | grid search hyperparameter tuning | Essayer toutes les combinaisons d'une petite liste de valeurs.
- Le sur-ajustement | overfitting evaluation set | Des réglages parfaits pour le jeu de test, et moins bons ailleurs.
- La validation par groupes | group k-fold data leakage | Garder ensemble les exemples liés, pour qu'aucun ne « fuie » dans la partie de réglage.
- L'optimisation bayésienne | bayesian optimization hyperopt | Choisir les prochains essais d'après les résultats des précédents.
