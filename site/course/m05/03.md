@@ brief
- **Streamlit** fait une interface web avec du Python seul : `st.text_input` pour la question, `st.button` pour le bouton, `st.write` pour la réponse. Pas de HTML, pas de JavaScript.
- 🔑 Le modèle de Streamlit est surprenant : à **chaque** interaction (une lettre validée, un clic), il relance **tout le script**, de la première à la dernière ligne. `st.button("Ask")` vaut `True` seulement pendant le passage qui suit le clic.
- Conséquence directe : tout ce qui est en haut du script, comme `create_assistant()`, est refait à chaque passage. Avec la leçon telle quelle, la FAQ est retéléchargée et l'index reconstruit plusieurs fois par question.
- La solution : `@st.cache_resource` sur la fonction qui crée l'assistant. Streamlit garde l'objet en mémoire et le rend au passage suivant, sans rappeler la fonction.
- `uv run streamlit run app.py` lance un serveur web sur le port 8501. Codespaces le détecte et t'en donne le lien.

@@ practice
Corrige l'application pour qu'elle ne construise l'assistant **qu'une fois**, et qu'elle refuse les questions vides.

@@ constraints
- Une fonction `get_assistant()` décorée par `@st.cache_resource`, qui appelle `create_assistant()`
- Dans la barre latérale, le temps qu'a pris la construction de l'index (`st.sidebar`)
- Le bouton Ask est grisé tant que la question est vide ou ne contient que des espaces
- `assistant.py` ne change pas

@@ guide
### 1. Le cache

Une fonction décorée par `@st.cache_resource` n'est exécutée qu'au premier passage. Aux suivants, Streamlit renvoie l'objet qu'elle a rendu la première fois, le **même** objet. C'est ce qu'on veut pour une connexion, un client ou un index.

### 2. Mesurer

`time.time()` avant et après `create_assistant()`. La fonction peut renvoyer deux valeurs : l'assistant et la durée.

### 3. Griser le bouton

`st.button` accepte `disabled=`. `user_input.strip()` est une chaîne vide si la question n'a que des espaces, et une chaîne vide vaut `False`.

@@ hints
- Si le temps affiché dans la barre latérale change à chaque clic, ton cache ne marche pas : vérifie le décorateur.
- `st.cache_data` et `st.cache_resource` ne font pas la même chose : relis l'erreur provoquée plus bas avant de choisir.
- `disabled=not user_input.strip()`.

@@ solution
~~~python
import time

import streamlit as st

from assistant import create_assistant


@st.cache_resource
def get_assistant():
    start = time.time()
    assistant = create_assistant()
    return assistant, time.time() - start


assistant, load_time = get_assistant()

st.title("Course Assistant")
st.sidebar.write(f"Index prêt en {load_time:.1f} s")

user_input = st.text_input("Enter your question:")

if st.button("Ask", disabled=not user_input.strip()):
    with st.spinner("Processing..."):
        answer = assistant.rag(user_input)
        st.success("Completed!")
        st.write(answer)
~~~

Le temps de la barre latérale ne bouge plus d'une question à l'autre : c'est la preuve que l'index n'est plus reconstruit. Pour le reconstruire (si la FAQ a changé), le menu ⋮ de Streamlit a **Clear cache**, ou relance simplement le serveur.

@@ breakfix
Remplace `@st.cache_resource` par `@st.cache_data` et recharge la page. Que se passe-t-il, et pourquoi ce décorateur ne convient-il pas ici ?

@@ breakfix-hints
- Lis le message d'erreur en entier : il nomme la bibliothèque qu'utilise `st.cache_data`.
- Que contient l'assistant ? Un index, mais aussi un client OpenAI, avec ses connexions réseau.

@@ breakfix-answer
L'application plante dès l'ouverture : `Cannot serialize the return value (of type tuple) in get_assistant()`. `st.cache_data` **copie** la valeur avec `pickle`, pour rendre à chaque passage une copie neuve. C'est parfait pour un tableau de données, mais un client OpenAI ne se copie pas : il tient des connexions ouvertes.

La règle de Streamlit : `st.cache_data` pour des **données** (un DataFrame, le résultat d'une requête), `st.cache_resource` pour des **ressources** partagées (un client, une connexion, un modèle). Le message d'erreur le dit lui-même à la fin.

@@ explain
Pourquoi Streamlit relance-t-il tout le script à chaque clic ? Qu'est-ce que ce choix simplifie, et quel prix fait-il payer ?

@@ cles
- Le modèle d'exécution de Streamlit | streamlit execution model rerun | Tout le script tourne à chaque interaction, de haut en bas.
- Le cache de ressources | st.cache_resource vs st.cache_data | Garder un objet coûteux entre deux passages, sans le copier.
- La sérialisation | python pickle serialization | Transformer un objet en octets pour le copier ou le stocker.
