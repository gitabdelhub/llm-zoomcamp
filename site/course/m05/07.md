@@ brief
- Avant Grafana, un tableau de bord **dans Streamlit**. Pour beaucoup de projets, c'est tout ce qu'il faut : le nombre de conversations, le temps de réponse moyen, le coût total, les tokens moyens, deux courbes et les dernières conversations.
- `get_stats()` fait le calcul **dans Postgres** (`COUNT`, `AVG`, `SUM`) : une seule ligne revient, quelle que soit la taille de la table.
- `dashboard.py` tourne sur le port **8502**, puisque l'application de chat occupe déjà le 8501.
- La leçon le dit : si tu t'arrêtes là, SQLite suffirait, sans Docker. Postgres sert surtout à Grafana, qui s'y branche plus facilement.
- 🔑 Une **moyenne** cache les mauvais moments. Si 10 % des réponses prennent 8 s et les autres 1 s, la moyenne dit 1,7 s, alors qu'un utilisateur sur dix attend 8 s. Le **p95** (le temps sous lequel tombent 95 % des réponses) dit 8 s.

@@ verified
- Sur une base **vide**, le `dashboard.py` de la leçon plante dès la première ligne de chiffres : `TypeError: unsupported format string passed to NoneType.__format__`. Sans aucune ligne, `AVG(...)` et `SUM(...)` renvoient `NULL`, que Python reçoit comme `None`, et `f"{None:.2f}"` est impossible.
- Avec 100 réponses dont 10 à 8 s et 90 à 1 s, Postgres donne une moyenne de **1,70 s** et `percentile_cont(0.95)` donne **8 s**.

@@ practice
Rends le tableau de bord **solide** et **honnête** : il doit s'ouvrir sur une base vide, et montrer le p95 du temps de réponse à côté de la moyenne.

@@ constraints
- Sur une base vide, le tableau de bord affiche un message (`st.info`) et s'arrête proprement, sans erreur
- `get_stats()` renvoie aussi le p95 du temps de réponse, calculé par Postgres
- Le coût total vaut 0 (et pas `None`) sur une base vide
- Une métrique « p95 response time » à côté de la moyenne

@@ guide
### 1. Le percentile dans Postgres

`percentile_cont(0.95) WITHIN GROUP (ORDER BY response_time)` : la valeur sous laquelle tombent 95 % des temps. C'est une fonction d'agrégation, comme `AVG` : elle va dans le même `SELECT`.

### 2. Les NULL

`COALESCE(SUM(cost), 0)` remplace `NULL` par 0. Pour une moyenne, 0 serait un mensonge : laisse `None`, et ne l'affiche pas.

### 3. S'arrêter

`st.stop()` arrête le script ici : rien de ce qui suit n'est exécuté ni affiché.

@@ hints
- Le champ `total` vaut 0 sur une base vide : c'est lui qu'il faut tester, avant tout `f"{...:.2f}"`.
- Ajoute le p95 au dataclass `Stats`, et décale les index de `row[...]` : ils changent quand tu ajoutes une colonne au `SELECT`.
- Pour tester la base vide sans perdre tes données : une autre base, avec `POSTGRES_DB=...` devant la commande.

@@ solution
Dans `db_query.py` :

~~~python
@dataclass
class Stats:
    total: int
    avg_response_time: float | None
    p95_response_time: float | None
    total_cost: float
    avg_tokens: float | None


def get_stats():
    conn = get_db_connection()
    try:
        with conn.cursor() as cur:
            cur.execute("""
                SELECT
                    COUNT(*),
                    AVG(response_time),
                    percentile_cont(0.95) WITHIN GROUP (ORDER BY response_time),
                    COALESCE(SUM(cost), 0),
                    AVG(total_tokens)
                FROM conversations
            """)
            row = cur.fetchone()
    finally:
        conn.close()
    return Stats(
        total=row[0],
        avg_response_time=row[1],
        p95_response_time=row[2],
        total_cost=row[3],
        avg_tokens=row[4],
    )
~~~

Dans `dashboard.py`, à la place des quatre métriques :

~~~python
stats = get_stats()

if stats.total == 0:
    st.info("Pas encore de conversation. Pose une question dans l'application, ou lance generate_data.py.")
    st.stop()

col1, col2, col3, col4, col5 = st.columns(5)
col1.metric("Total conversations", stats.total)
col2.metric("Avg response time", f"{stats.avg_response_time:.2f}s")
col3.metric("p95 response time", f"{stats.p95_response_time:.2f}s")
col4.metric("Total cost", f"${stats.total_cost:.4f}")
col5.metric("Avg tokens", f"{stats.avg_tokens:.0f}")
~~~

J'ai testé les deux cas avec l'outil de test de Streamlit : sur une base vide, seul le message s'affiche ; avec 100 conversations, les cinq métriques sont là.

@@ explain
Pourquoi surveiller le p95 du temps de réponse plutôt que la moyenne ? Dans quel cas les deux racontent-ils la même chose ?

@@ cles
- Les percentiles de latence | latency percentiles p95 p99 | Le temps sous lequel tombent 95 % ou 99 % des requêtes.
- NULL et les agrégats | sql aggregate functions null empty table | Sur zéro ligne, AVG et SUM renvoient NULL, pas 0.
- COALESCE | sql coalesce | Remplacer NULL par une valeur par défaut.
