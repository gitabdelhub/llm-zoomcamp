@@ brief
- Le LLM juge du module 4, cette fois **en ligne** : après chaque réponse, un second appel au LLM dit si elle est pertinente (`RELEVANT`, `PARTLY_RELEVANT`, `NON_RELEVANT`), avec une explication.
- 🔑 La grande différence avec le module 4 : il n'y a plus de **réponse de référence**. Le juge ne voit que la question et la réponse, et doit trancher seul. Le travail est plus dur, d'où des instructions plus précises.
- La **sortie structurée** (un modèle pydantic `RelevanceVerdict`) donne une étiquette propre au lieu d'un texte à analyser. `llm_structured_retry` réessaie si le JSON ne colle pas au modèle, ce qui arrive rarement.
- Demander une `explanation` force le juge à raisonner **avant** de choisir son étiquette : l'étiquette est souvent meilleure.
- Le verdict va dans la même table `feedback`, avec `source = "judge"`. On peut alors comparer l'avis du juge et celui des utilisateurs.
- Le coût : un appel de plus par question. La leçon le dit, en production on juge en arrière-plan, on suit le coût du juge à part, et on n'en juge qu'une partie (une sur dix, par exemple).

@@ practice
Fais du juge une dépense **maîtrisée** : il ne juge qu'une partie des réponses, réglable sans toucher au code, et tu vois ce qu'il coûte.

@@ constraints
- Une variable d'environnement `JUDGE_RATE` : `1.0` juge tout (par défaut), `0.1` une réponse sur dix en moyenne, `0` aucune
- Une fonction `maybe_judge(question, answer)` qui renvoie `None` si la réponse n'est pas jugée, sinon `(relevance, explanation, cost)`
- Le coût du juge est calculé avec la `calculate_cost` de `metrics.py`, et affiché sous la réponse
- Le schéma des tables ne change pas
- Avec `JUDGE_RATE=0`, aucune ligne `judge` n'est écrite

@@ guide
### 1. Tirer au sort

`random.random()` renvoie un nombre entre 0 et 1. `random.random() < rate` est vrai dans une proportion `rate` des cas.

### 2. Garder l'usage

`llm_structured_retry` renvoie deux choses : le verdict **et** l'usage. Le `evaluate_relevance` de la leçon jette l'usage ; ta fonction le garde pour calculer le coût.

### 3. Dans l'application

Dans le bloc Ask de la leçon 8, après `save_conversation` : `verdict = maybe_judge(user_input, answer)`. S'il n'est pas `None`, enregistre-le avec `save_feedback(conversation_id, "judge", ...)` et range-le dans `st.session_state.last` pour l'afficher.

@@ hints
- Lis `JUDGE_RATE` à chaque appel (`os.getenv`), pas une seule fois à l'import : tu pourras le changer sans redémarrer certains outils.
- Tu peux réutiliser `RelevanceVerdict`, `judge_instructions` et `judge_prompt` en les important de `judge.py`.
- Pour lancer l'application avec un autre taux : `JUDGE_RATE=0.1 make chat`.

@@ solution
`judge_sampling.py` :

~~~python
import os
import random

from openai import OpenAI

from evaluation_utils import llm_structured_retry
from judge import RelevanceVerdict, judge_instructions, judge_prompt
from metrics import calculate_cost

JUDGE_MODEL = "gpt-5.4-mini"


def judge_rate():
    # 1.0 : on juge tout ; 0.1 : une réponse sur dix, en moyenne.
    return float(os.getenv("JUDGE_RATE", "1.0"))


def maybe_judge(question, answer, client=None):
    """Renvoie (relevance, explanation, cost), ou None si on ne juge pas cette réponse."""
    if random.random() >= judge_rate():
        return None
    client = client or OpenAI()
    prompt = judge_prompt.format(question=question, answer=answer)
    result, usage = llm_structured_retry(client, judge_instructions, prompt, RelevanceVerdict, model=JUDGE_MODEL)
    return result.relevance, result.explanation, calculate_cost(JUDGE_MODEL, usage)
~~~

Dans le bloc Ask de `app.py` :

~~~python
        conversation_id = save_conversation(record, user_input, "llm-zoomcamp")
        verdict = maybe_judge(user_input, answer)
        if verdict is not None:
            relevance, explanation, judge_cost = verdict
            save_feedback(conversation_id, "judge", relevance=relevance, explanation=explanation)
        st.session_state.last = {"answer": answer, "record": record,
                                 "conversation_id": conversation_id, "verdict": verdict}
~~~

Et dans l'affichage :

    verdict = last["verdict"]

Testé avec un faux serveur OpenAI : `JUDGE_RATE=0` ne fait aucun appel, `JUDGE_RATE=1` juge chaque réponse, et `JUDGE_RATE=0.1` en a jugé 15 sur 200, un tirage au sort normal autour de 20.

@@ selfcheck
- Avec `JUDGE_RATE=0`, `SELECT COUNT(*) FROM feedback WHERE source = 'judge';` n'augmente pas
- Avec le taux par défaut, chaque réponse a sa pertinence et le coût du juge
- Le coût du juge est en général plus petit que celui de la réponse : son prompt n'a pas les 5 documents du contexte

@@ cles
- Le LLM juge en ligne | online LLM as a judge without reference | Juger une réponse sans réponse de référence, sur le trafic réel.
- L'échantillonnage | sampling evaluation production LLM | N'évaluer qu'une partie du trafic, pour une fraction du coût.
- L'alignement du juge | LLM judge alignment human labels | Régler le juge jusqu'à ce qu'il soit d'accord avec des humains.
