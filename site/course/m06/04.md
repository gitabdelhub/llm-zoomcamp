@@ brief
- **LangChain** emballe Elasticsearch dans une interface plus courte : `ElasticsearchRetriever`, construit à partir d'une fonction qui fabrique la requête hybride. L'index ne change pas, seul le code de recherche change.
- Les embeddings passent par `HuggingFaceEmbeddings` (le même modèle `multi-qa-MiniLM-L6-cos-v1` que la leçon 3), et `retriever.invoke(question)` renvoie des documents LangChain (`page_content` et `metadata`).
- Les résultats sont **les mêmes** qu'en Elasticsearch direct (hit rate 0,925, MRR 0,851) : LangChain ne change pas la requête, il change l'écriture.
- 🔑 L'intérêt de LangChain apparaît quand la recherche n'est qu'une étape d'une chaîne plus longue : recherche, prompt, LLM, analyse de la sortie. Pour une seule recherche, le code direct est aussi court, et tu vois tout ce qui se passe.

@@ verified
- Pas lancé ici : Elasticsearch et les modèles Hugging Face sont bloqués dans mon environnement. Les chiffres sont ceux de la leçon.
- `langchain-huggingface` installe sentence-transformers, donc PyTorch. Si tu l'essaies dans ton Codespace, ajoute l'index PyTorch CPU du module 2 **avant** le `uv add`, sinon uv télécharge la version GPU, bien plus lourde.
