Avec les boosts écrits dans la leçon : hit rate **0,951**, MRR **0,909**. Le gain est **réel sur le MRR**, nul sur le hit rate, alors que la leçon annonce « nettement mieux » sur les deux.

- Les boosts écrits dans `search` (2.11, 1.46…) sont ceux de l'auteur, pas ceux que ton `simple_optimize` vient de trouver.

@@ practice
Refais le réglage des boosts proprement sur les données du projet fini : un découpage par **exercice** et tiré au hasard, un objectif qui bouge vraiment, et plusieurs graines pour voir si le gain tient.

@@ constraints
- Les fichiers `data/data.csv` et `data/ground-truth-retrieval.csv` du dépôt `fitness-assistant`, dans `mon-travail/module-07/`
- Une fonction `split_by_document(df, val_frac, seed)` : toutes les questions d'un même exercice vont du même côté, et elle s'arrête si une des deux parties est vide
- La recherche aléatoire optimise le **MRR**, avec son propre générateur aléatoire (`random.Random(seed)`), et garde « pas de boost » si rien ne fait mieux
- Pour 3 graines : hit rate et MRR sur le test, sans boost et avec le boost trouvé

@@ guide
### 1. Les données

Télécharge les deux CSV depuis `https://raw.githubusercontent.com/alexeygrigorev/fitness-assistant/main/data/`, avec `curl -L -o`. Pas besoin de clé d'API pour cet exercice : tout est local.

### 2. Le découpage

Mélange la liste des `id` uniques avec `random.Random(seed).shuffle`, prends les premiers 30 % pour la validation, puis filtre le DataFrame avec `isin`.

### 3. L'objectif

`evaluate` rend les deux métriques ; l'objectif lit `["mrr"]`. Commence avec le score « sans boost » comme meilleur score.

### 4. Les graines

Une boucle sur 3 graines, qui change à la fois le découpage et les tirages. Compte environ 2 minutes en tout.

@@ hints
- Un `id` présent dans la validation ne doit jamais apparaître dans le test : `assert not set(val_ids) & set(test_ids)`.
- Si ton MRR avec boost est parfois plus bas que sans boost sur le test, c'est que tu gardes un boost même quand il ne bat pas le score de départ.
- `random.uniform` utilise un générateur global : deux appels de suite à ta fonction ne donnent pas les mêmes tirages. Un `random.Random(seed)` local, si.

@@ solution
~~~python
import random
import pandas as pd
from minsearch import Index

FIELDS = ["exercise_name", "type_of_activity", "type_of_equipment", "body_part",
          "type", "muscle_groups_activated", "instructions"]

documents = pd.read_csv("data/data.csv").to_dict(orient="records")
index = Index(text_fields=FIELDS, keyword_fields=["id"])
index.fit(documents)
df_question = pd.read_csv("data/ground-truth-retrieval.csv")


def search(query, boost=None):
    return index.search(query=query, filter_dict={}, boost_dict=boost or {}, num_results=10)


def evaluate(ground_truth, boost=None):
    relevance = [[d["id"] == q["id"] for d in search(q["question"], boost)] for q in ground_truth]
    hit_rate = sum(True in line for line in relevance) / len(relevance)
    mrr = sum(next((1 / (r + 1) for r, ok in enumerate(line) if ok), 0) for line in relevance) / len(relevance)
    return {"hit_rate": round(hit_rate, 3), "mrr": round(mrr, 3)}


def split_by_document(df, val_frac, seed):
    ids = sorted(df["id"].unique())
    random.Random(seed).shuffle(ids)
    val_ids = set(ids[: int(len(ids) * val_frac)])
    val, test = df[df["id"].isin(val_ids)], df[~df["id"].isin(val_ids)]
    assert len(val) and len(test), "une des deux parties est vide"
    return val.to_dict(orient="records"), test.to_dict(orient="records")


def optimize(gt_val, seed, n_iterations=20):
    rng = random.Random(seed)
    best, best_score = {}, evaluate(gt_val)["mrr"]
    for _ in range(n_iterations):
        params = {f: rng.uniform(0.0, 3.0) for f in FIELDS}
        score = evaluate(gt_val, params)["mrr"]
        if score > best_score:
            best, best_score = params, score
    return best


for seed in range(3):
    gt_val, gt_test = split_by_document(df_question, val_frac=0.3, seed=seed)
    boost = optimize(gt_val, seed)
    print(f"seed {seed} : {len(gt_val)} val / {len(gt_test)} test | "
          f"sans boost {evaluate(gt_test)} | avec boost {evaluate(gt_test, boost)}")
~~~

~~~text
seed 0 : 310 val / 725 test | sans boost {'hit_rate': 0.948, 'mrr': 0.813} | avec boost {'hit_rate': 0.948, 'mrr': 0.91}
seed 1 : 310 val / 725 test | sans boost {'hit_rate': 0.956, 'mrr': 0.831} | avec boost {'hit_rate': 0.953, 'mrr': 0.92}
seed 2 : 310 val / 725 test | sans boost {'hit_rate': 0.943, 'mrr': 0.826} | avec boost {'hit_rate': 0.948, 'mrr': 0.9}
~~~

Le MRR gagne environ 0,09 sur les trois graines : ce gain-là est solide. Le hit rate bouge de quelques millièmes dans les deux sens : c'est du bruit.

@@ explain
Pourquoi découper par exercice plutôt que par question ? Et pourquoi un objectif qui plafonne (le hit rate à 0,93) rend-il la recherche aléatoire presque inutile ?

@@ cles
- La recherche aléatoire | random search hyperparameter optimization | Tirer des réglages au hasard et garder le meilleur, sur la validation seulement.
- Le découpage par groupe | group k-fold data leakage | Garder toutes les lignes d'un même objet du même côté.
- La graine aléatoire | random seed reproducibility | Le même tirage à chaque lancement, pour comparer.
