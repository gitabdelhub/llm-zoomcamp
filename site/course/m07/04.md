@@ brief
- Du notebook à une vraie application : le code passe dans des fichiers (`ingest.py` construit l'index, `rag.py` cherche et appelle le LLM), puis une **API Flask** avec une route `POST /question`.
- minsearch vit en mémoire : l'**ingestion** se fait au démarrage de l'application. Avec Elasticsearch ou Postgres, ce serait une étape séparée.
- `rag` rend maintenant un dictionnaire : la réponse, le modèle, le temps et les tokens, prêts pour le monitoring.
- 🔑 Une API reçoit n'importe quoi. Elle doit répondre **400** à une mauvaise requête, jamais **500**, et ne jamais montrer son code à qui l'appelle.

@@ verified
J'ai lancé l'API de la leçon avec un `rag` factice (sans appel au LLM) et envoyé de mauvaises requêtes :

- `{"q": "..."}` sans le champ `question` : **500**, avec une page `KeyError` du **débogueur Werkzeug** qui montre le traceback.
- Un corps qui n'est pas du JSON : **415**, en HTML et non en JSON.
- `{"question": "   "}` : **200**, la question vide part au LLM et coûte un appel. `{"question": 42}` : **500**.
- Sur `/feedback` (leçon 5) : `"feedback": true` et `"feedback": 1.0` passent le test `feedback not in [1, -1]`, car en Python `True == 1` et `1.0 == 1`.
- `app.run(debug=True, host="0.0.0.0")` écoute sur **toutes** les adresses avec le débogueur actif. Le débogueur a une console Python, protégée par un PIN ; ne laisse jamais ce mode sur un port ouvert. Le dépôt final lance **Gunicorn** à la place.
- L'arborescence de la leçon met `app.py` à la racine et `rag.py` dans `fitness_assistant/` : `from rag import rag` ne trouve pas le module. Dans le dépôt final, `app.py` est dans `fitness_assistant/`, à côté de `rag.py`.

@@ declic
- [05-03] Au module 5, l'interface était une page Streamlit. Ici, une API : un autre programme peut l'appeler, et donc lui envoyer n'importe quoi.
- [DE:01-04] Au Zoomcamp DE, `-p 5432:5432` publiait le port de Postgres hors du conteneur. Une API qui écoute sur `0.0.0.0` derrière un port publié est joignable de l'extérieur : c'est pour ça que le mode débogage y est dangereux.

@@ practice
Rends l'API robuste et **teste-la sans appeler le LLM** : Flask a un client de test, et pytest peut remplacer `rag` par une fonction factice.

@@ constraints
- `POST /question` répond 400 en JSON si le corps n'est pas un objet JSON, si `question` manque, n'est pas un texte ou est vide après `strip()`
- `POST /feedback` répond 400 si `feedback` n'est pas exactement l'entier 1 ou -1 (`True`, `1.0`, `"1"` refusés)
- Un `test_app.py` qui remplace `rag` avec `monkeypatch`, et vérifie qu'aucune mauvaise requête n'appelle `rag`
- Aucun `debug=True` dans le code : l'API se lance avec Gunicorn

@@ guide
### 1. Lire le corps sans planter

`request.get_json(silent=True)` rend `None` au lieu de lever une erreur ; vérifie ensuite que c'est un `dict`.

### 2. Valider les types

`isinstance(question, str)` puis `question.strip()`. Pour le feedback, `type(feedback) is int`, car `isinstance(True, int)` est vrai.

### 3. Tester

Importe le module (`import rag`, puis `rag.rag(...)` dans la route) : `monkeypatch.setattr(api.rag, "rag", fake)` remplace alors la fonction que la route appelle vraiment. `app.test_client()` envoie les requêtes, `json=` met le bon en-tête.

### 4. Lancer

`uv add gunicorn`, puis `uv run gunicorn --bind 0.0.0.0:5000 app:app`.

@@ hints
- Si ton `monkeypatch` ne remplace rien, regarde ton import : avec `from rag import rag`, la route garde l'ancienne fonction.
- `@pytest.mark.parametrize` teste toutes les mauvaises valeurs avec un seul test.
- Gunicorn ne lit pas `if __name__ == "__main__"` : il importe `app` dans le module `app`.

@@ solution
~~~python
# app.py
import uuid

from flask import Flask, jsonify, request

import rag

app = Flask(__name__)


def bad_request(message):
    return jsonify({"error": message}), 400


@app.post("/question")
def handle_question():
    data = request.get_json(silent=True)
    if not isinstance(data, dict):
        return bad_request("Le corps doit être un objet JSON")
    question = data.get("question")
    if not isinstance(question, str) or not question.strip():
        return bad_request("'question' doit être un texte non vide")
    answer_data = rag.rag(question.strip())
    return jsonify({
        "conversation_id": str(uuid.uuid4()),
        "question": question.strip(),
        "answer": answer_data["answer"],
    })


@app.post("/feedback")
def handle_feedback():
    data = request.get_json(silent=True)
    if not isinstance(data, dict):
        return bad_request("Le corps doit être un objet JSON")
    conversation_id, feedback = data.get("conversation_id"), data.get("feedback")
    if not isinstance(conversation_id, str) or not conversation_id:
        return bad_request("'conversation_id' manquant")
    if type(feedback) is not int or feedback not in (1, -1):
        return bad_request("'feedback' doit valoir 1 ou -1")
    return jsonify({"message": f"Feedback received: {feedback}"})
~~~

~~~python
# test_app.py
import pytest

import app as api


@pytest.fixture
def client(monkeypatch):
    calls = []

    def fake_rag(question, model="gpt-5.4-mini"):
        calls.append(question)
        return {"answer": "ok"}

    monkeypatch.setattr(api.rag, "rag", fake_rag)
    api.app.testing = True
    with api.app.test_client() as c:
        c.calls = calls
        yield c


def test_question_ok(client):
    r = client.post("/question", json={"question": "  What exercises target the chest?  "})
    assert r.status_code == 200
    assert r.json["question"] == "What exercises target the chest?"
    assert client.calls == ["What exercises target the chest?"]


@pytest.mark.parametrize("body", [{}, {"q": "x"}, {"question": ""}, {"question": "   "}, {"question": 42}, [1, 2]])
def test_question_rejected(client, body):
    r = client.post("/question", json=body)
    assert r.status_code == 400 and "error" in r.json
    assert client.calls == []


def test_question_not_json(client):
    r = client.post("/question", data="question=chest")
    assert r.status_code == 400 and "error" in r.json


@pytest.mark.parametrize("value", [True, 1.0, 0, 2, "1", None])
def test_feedback_rejected(client, value):
    r = client.post("/feedback", json={"conversation_id": "abc", "feedback": value})
    assert r.status_code == 400


@pytest.mark.parametrize("value", [1, -1])
def test_feedback_ok(client, value):
    assert client.post("/feedback", json={"conversation_id": "abc", "feedback": value}).status_code == 200
~~~

@@ explain
Pourquoi une erreur 500 est-elle un bug même quand la requête était mauvaise ? Et pourquoi `type(x) is int` plutôt que `isinstance(x, int)` pour le feedback ?

@@ cles
- La validation des entrées | input validation REST API 400 | Refuser une mauvaise requête avant de dépenser quoi que ce soit.
- Le client de test de Flask | flask test client pytest | Appeler ton API dans un test, sans serveur.
- monkeypatch | pytest monkeypatch setattr | Remplacer une fonction le temps d'un test.
- Gunicorn | gunicorn flask production | Un vrai serveur WSGI, à la place du serveur de développement.
