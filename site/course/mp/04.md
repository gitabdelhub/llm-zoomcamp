@@ brief
- Deux critères. L'**interface** : un script ou un notebook vaut 1 point ; une interface (Streamlit) ou une API (FastAPI, Flask) en vaut 2. Le **monitoring** : les avis des utilisateurs **et** un tableau de bord d'**au moins 5 graphiques** pour 2 points ; l'un ou l'autre pour 1.
- Chaque question part dans Postgres avec sa réponse, le temps, les tokens, le coût, l'avis du juge et les `id` des passages. Les 👍 et 👎 vont dans une table à part, liée par l'`id` de la conversation.
- Les 5 graphiques se choisissent pour répondre à des questions : est-ce que ça coûte trop, est-ce lent, est-ce que les réponses sont bonnes, est-ce que les gens sont contents, de quoi parlent-ils.
- 🔑 Le monitoring ne vaut que si les chiffres sont **justes** : un coût à 0 ou un avis impossible à enregistrer, c'est un tableau de bord qui ment.

@@ predict
Tu as ces 5 graphiques : nombre de questions par heure, temps de réponse moyen, coût par jour, part de 👍, part de `RELEVANT` selon le juge. Lequel peut te mentir le plus facilement, et par quoi le compléter ?

@@ predict-answer
Le temps de réponse **moyen** : 95 réponses en 2 s et 5 en 40 s donnent 3,9 s de moyenne, qui ne ressemble à aucune vraie réponse. Le **p95** montre ce que vivent les utilisateurs les plus mal servis. La part de 👍 ment aussi sans le nombre de votes à côté : 100 % sur 2 votes ne dit rien.

@@ guide
### 1. L'interface

Streamlit si tu veux un écran, FastAPI ou Flask si tu veux une API. Dans Streamlit, garde la réponse dans `st.session_state`, sinon elle disparaît au clic sur 👍.

### 2. Le stockage

Le schéma du module 5 : `conversations` et `feedback`. Une contrainte d'unicité sur le vote, et un upsert si l'utilisateur change d'avis.

### 3. Le tableau de bord

Le provisioning du défi 5 : un fichier de source de données et un fichier de tableau de bord, montés dans le conteneur Grafana. Le p95 : `percentile_cont(0.95) WITHIN GROUP (ORDER BY response_time)`.

### 4. Des données pour tester

Des fausses conversations, mais cohérentes (leçon 11 du module 5), pour voir tes graphiques avant les premiers vrais utilisateurs.

@@ hints
- Un graphique vide dans Grafana vient souvent d'un filtre de temps : vérifie que la colonne de temps est bien un `timestamptz`.
- Le coût par jour : `date_trunc('day', timestamp)` et `sum(cost)`.
- Un 6e graphique utile : les questions les plus fréquentes, pour savoir quoi améliorer.

@@ solution
Cinq requêtes Grafana sur l'exemple des jeux de société, à adapter à ton schéma :

~~~sql
-- 1. Questions par heure
SELECT date_trunc('hour', timestamp) AS time, count(*) FROM conversations
WHERE $__timeFilter(timestamp) GROUP BY 1 ORDER BY 1;

-- 2. Temps de réponse : médiane et p95
SELECT date_trunc('hour', timestamp) AS time,
       percentile_cont(0.5) WITHIN GROUP (ORDER BY response_time) AS p50,
       percentile_cont(0.95) WITHIN GROUP (ORDER BY response_time) AS p95
FROM conversations WHERE $__timeFilter(timestamp) GROUP BY 1 ORDER BY 1;

-- 3. Coût par jour
SELECT date_trunc('day', timestamp) AS time, sum(cost) FROM conversations
WHERE $__timeFilter(timestamp) GROUP BY 1 ORDER BY 1;

-- 4. Avis du juge
SELECT relevance, count(*) FROM conversations
WHERE $__timeFilter(timestamp) GROUP BY 1;

-- 5. Avis des utilisateurs, avec le nombre de votes
SELECT count(*) FILTER (WHERE feedback = 1) AS pouce_haut,
       count(*) FILTER (WHERE feedback = -1) AS pouce_bas
FROM feedback WHERE $__timeFilter(timestamp);
~~~
