@@ brief
- Chaque agent de code (Claude Code, Codex, Copilot) garde sur ta machine une trace de chaque session : un fichier **JSONL**, une ligne JSON par événement, avec les modèles utilisés, les tokens, les outils appelés. Des données précieuses, mais très imbriquées.
- Le workshop les transforme en tables et en tableaux de bord, en deux parties : **les logs locaux** (des fichiers sur le disque) puis **une API hébergée** (comme Logfire ou Langfuse en entreprise).
- La nouveauté par rapport au workshop dlt du Zoomcamp DE : tu n'écris pas la pipeline à la main. Tu la **décris** à un agent de code, et le **dltHub AI workbench** (des toolkits, des skills et un serveur MCP) lui apporte ce qu'il faut savoir sur dlt.
- Les outils : **dlt** pour charger, **DuckDB** pour stocker (un fichier, pas de serveur), **marimo** pour les tableaux de bord, et la **plateforme dltHub** pour déployer.

@@ explain
Pourquoi charger des logs JSONL dans une base, au lieu de les lire avec Python à chaque question ? Et qu'est-ce que l'AI workbench apporte à un agent de code qui « connaît déjà » dlt ?

@@ cles
- Le format JSONL | JSON lines format | Une ligne, un objet JSON : facile à écrire en continu, pénible à interroger.
- dlt | dlt data load tool python | Charger des données imbriquées dans une base, avec un schéma déduit et des tables enfants.
- DuckDB | duckdb in-process analytical database | Une base analytique dans un fichier, sans serveur.
- Le Model Context Protocol | model context protocol MCP server | Donner des outils à un agent de code : ici, inspecter tes pipelines et tes tables.
