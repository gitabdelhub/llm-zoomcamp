- Le tableau de bord du workshop suit un motif simple : une cellule de **données** (du SQL qui renvoie un DataFrame), puis une cellule de **graphique** (Altair).

@@ solution
Deux paires de cellules, à ajouter avant la dernière ligne `if __name__ == "__main__":` :

~~~python
@app.cell
def _(mo):
    mo.md("""
    ## Modèles et tokens
    """)
    return


@app.cell
def _(dataset):
    df_models = dataset("""
        SELECT
            data->>'$.message.model' AS model,
            COUNT(*) AS calls,
            SUM(CAST(data->>'$.message.usage.output_tokens' AS INTEGER)) AS output_tokens
        FROM log_records
        WHERE type = 'assistant'
        GROUP BY 1
        ORDER BY output_tokens DESC
    """).df()
    return (df_models,)


@app.cell
def _(alt, df_models):
    _chart = alt.Chart(df_models).mark_bar().encode(
        x=alt.X("model:N", sort="-y"),
        y="output_tokens:Q",
        color="model:N",
        tooltip=["model:N", "calls:Q", "output_tokens:Q"],
    ).properties(title="Tokens de sortie par modèle")
    _chart
    return


@app.cell
def _(dataset):
    df_tokens_day = dataset("""
        SELECT
            DATE_TRUNC('day', timestamp) AS day,
            data->>'$.message.model' AS model,
            SUM(CAST(data->>'$.message.usage.output_tokens' AS INTEGER)) AS output_tokens
        FROM log_records
        WHERE type = 'assistant'
        GROUP BY 1, 2
        ORDER BY 1, 2
    """).df()
    return (df_tokens_day,)


@app.cell
def _(alt, df_tokens_day):
    _chart = alt.Chart(df_tokens_day).mark_bar().encode(
        x="day:T",
        y="output_tokens:Q",
        color="model:N",
        tooltip=["day:T", "model:N", "output_tokens:Q"],
    ).properties(title="Tokens de sortie par jour")
    _chart
    return
~~~

@@ breakfix
Pour aller vite, tu copies la cellule de graphique de la section « Modèles », et dans les deux cellules tu appelles ta variable `chart` au lieu de `_chart`. Le notebook refuse de lancer ces cellules. Que dit marimo, et pourquoi le code officiel écrit-il `_chart` partout ?

@@ breakfix-hints
- Dans marimo, une cellule déclare les variables qu'elle **définit** et celles qu'elle **lit**. Que se passe-t-il si deux cellules définissent la même ?
- Dans quel ordre marimo exécute-t-il les cellules : celui du fichier, ou un autre ?
- Que change le `_` au début d'un nom de variable, pour marimo ?

@@ breakfix-answer
marimo affiche `MultipleDefinitionError: The variable 'chart' was defined by another cell`, et ne lance aucune des deux.

marimo n'exécute pas les cellules dans l'ordre du fichier, mais dans l'ordre de leurs **dépendances** : la cellule qui définit `df_models` passe avant celles qui la lisent. Pour que cet ordre soit unique, chaque variable globale doit avoir **une seule** cellule qui la définit. Deux cellules qui définissent `chart`, et marimo ne saurait plus laquelle croire.

Un nom qui commence par `_` est **local** à sa cellule : marimo ne le partage pas, donc chaque cellule peut avoir son `_chart`. C'est ce qui permet au tableau de bord officiel d'en avoir un par graphique. C'est aussi ce qui évite l'erreur classique de Jupyter : une variable redéfinie plus bas, et des cellules qui affichent des résultats périmés.
